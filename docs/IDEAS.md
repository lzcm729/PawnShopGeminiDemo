## 入库后鉴定

**日期：** 2026-02-04
**相关系统：** 鉴定系统、夜间玩法
**状态：** 已采纳（2026-02-04 实现）

### 描述

夜间阶段可消耗 AP 对库存物品进行鉴定，补充玩家在收货阶段选择"盲收"后的鉴定能力。

### 设计意图

- 解决"盲收后永远无法知道真相"的问题
- 让价值跳变机制对盲收物品也能生效
- 为玩家提供"事后补救"的选择（以更高成本换取信息）

### 设计约束

- 消耗夜间行动点（AP）
- 成本应高于收货时鉴定（否则玩家总是盲收）
- 发现的特征只能获得信息，无法用于议价（已成交）

### 备注

来源于捡漏/打眼机制的设计讨论。与现有夜间玩法（工作台系统）不冲突，可作为独立功能或整合到库存盘点中。

## 黑市收购标签限额

**日期：** 2026-02-04
**相关系统：** 黑市系统
**状态：** 已采纳

### 描述

黑市收购改为每日每个标签只收购一件物品。

### 设计变更

| 项目 | 原设计 | 新设计 |
|------|--------|--------|
| 收购限额 | 每日总共 3 件（不分标签） | 每日每个标签 1 件 |
| 收购上限 | 固定 3 件 | 取决于当日收购标签数量 |

### 设计意图

- 增加策略性：玩家需要根据手中物品的标签来规划出售顺序
- 避免同标签物品扎堆出售
- 让每个标签的收购机会更珍贵

### 备注

需同步更新 `Designer/系统设计文档/黑市系统 (Black Market System).md`。

## 声誉归零失败机制

**日期：** 2026-02-04（初稿）→ 2026-02-05（设计完成）
**相关系统：** 声誉系统、游戏结束条件
**状态：** 已采纳

### 核心设计

三轴声誉重设计为**不可能三角**，任意一轴归零则游戏失败。

| 轴 | 含义 | 归零失败 |
|---|---|---|
| 人情 (Humanity) | 对客户的善意 | 众叛亲离，无人上门 |
| 商誉 (Credibility) | 履行承诺的守信度 | 被同行封杀，无法经营 |
| 清白 (Innocence) | 法律上的干净 | 被警方逮捕 |

**核心规则：玩家最多维持两轴在安全区，第三轴必然承压。**

### 三种生存策略

| 策略 | 维持高位 | 牺牲 | 玩家画像 |
|------|----------|------|----------|
| 善人商人 | 人情 + 商誉 | 清白 | 守信且善良，但为帮人不惜违法 |
| 守法好人 | 人情 + 清白 | 商誉 | 善良且守法，但常因善心而违约 |
| 正派商人 | 商誉 + 清白 | 人情 | 守信且守法，但冷酷无情 |

### 行为影响矩阵

**日常波动（±1）**：塑造倾向

| 行为 | 人情 | 商誉 | 清白 |
|------|------|------|------|
| 慈善档位 | +1 | - | - |
| 标准档位 | - | +1 | - |
| 高利贷 | -1 | - | - |
| 黑市出售 | - | - | -1 |

**关键决策（±3~5）**：通过物品衍生节点触发，必须形成张力

| 情境 | 选项A | 选项B |
|------|-------|-------|
| 赃物处理 | 收下：人情+2，清白-3 | 拒绝：清白+1，人情-2 |
| 逾期宽限 | 宽限：人情+2，商誉-2 | 严格执行：商誉+2，人情-2 |
| 黑道委托 | 接受：商誉+2，清白-3 | 拒绝/举报：清白+2，商誉-3 |
| 警方调查 | 配合：清白+2，人情-2，商誉-1 | 沉默：人情+1，商誉+1，清白-2 |

### 设计原则

> **日常行为塑造倾向，关键决策决定命运。**

- 关键决策事件通过**物品衍生节点**实现
- 每个关键决策必须有明确代价，形成不可能三角张力
- 低于安全阈值时 UI 闪烁警告（交互层后续设计）

### 实现建议

- **framework**: 重构声誉系统，将"黑道"轴改为"清白"轴，实现归零失败检测
- **content**: 设计关键决策的物品衍生节点（赃物处理、黑道委托、警方调查等）
- **interaction**: 声誉条低于阈值时的闪烁警告 UI

### 与现有设计的变更

- 原"黑道"轴 → 改为"清白"轴（语义反转）
- 原黑道正向积累 → 改为清白负向消耗
- 需更新声誉系统设计文档

## 议价推拉机制

**日期：** 2026-02-05
**相关系统：** 议价系统
**状态：** 已采纳

### 核心概念

**双向价格收敛**：议价从单向试探改为双向博弈。

- 玩家有 **Offer**（出价）
- NPC 有 **Ask**（要价）
- 推拉过程中双方向中间靠拢，直到重叠或耐心耗尽

```
NPC Ask:      $2000 → $1800 → $1600 → $1500
                    ↘      ↘      ↘
                      (收敛区)
                    ↗      ↗      ↗
Player Offer: $1000 → $1200 → $1400 → $1500
```

### 玩家行为定义

| 行为 | 条件 | 含义 |
|------|------|------|
| **让步** | Offer > 上轮 Offer | 玩家加价，展示诚意 |
| **坚持** | Offer = 上轮 Offer | 玩家维持报价，施压 |

（首次出价无"上轮"可比，单独处理）

### 每轮推拉流程

```
                         玩家出价 (Offer)
                               │
                               ▼
                        Offer ≥ Ask ?
                       ┌───────┴───────┐
                      Yes              No
                       │               │
                       ▼               ▼
                     成交        是否首次出价？
                               ┌───────┴───────┐
                              Yes              No
                               │               │
                               ▼               ▼
                          【首次出价】    【后续出价】
                               │               │
                               ▼               ▼
                          侮辱判定        行为判定
                               │         ┌────┴────┐
                    ┌──────────┤         ▼         ▼
                    ▼          ▼    Offer > 上轮  Offer = 上轮
                  侮辱      非侮辱       │         │
                    │          │        ▼         ▼
                    ▼          ▼      让步       坚持
                耐心 -2    耐心 -1       │         │
               Ask 不变   让步判定      ▼         ▼
                         (基础概率)  侮辱判定   侮辱判定
                                    ┌──┴──┐   ┌──┴──┐
                                   侮辱 非侮辱 侮辱 非侮辱
                                    │    │    │    │
                                    ▼    ▼    ▼    ▼
                                  -2   -1   -2   -1
                                  不变  基础  不变  ×0.5+累积
```

### 首次出价处理

| 条件 | 耐心消耗 | NPC 让步概率 |
|------|----------|--------------|
| 侮辱报价 | -2 | 0%（不让步） |
| 非侮辱 | -1 | 基础概率 |

### 后续出价处理

| 玩家行为 | 条件 | 耐心 | NPC 让步概率 |
|----------|------|------|--------------|
| 让步 + 侮辱 | Offer > 上轮 但 < 侮辱线 | -2 | 0% |
| 让步 + 非侮辱 | Offer > 上轮 且 ≥ 侮辱线 | -1 | **基础概率** |
| 坚持 + 侮辱 | Offer = 上轮 且 < 侮辱线 | -2 | 0% |
| 坚持 + 非侮辱 | Offer = 上轮 且 ≥ 侮辱线 | -1 | **基础×0.5 + 累积加成** |

**核心区别**：
- 玩家让步 → NPC 更愿意让步（你退一步，我也退一步）
- 玩家坚持 → NPC 不太愿意让步（你不动，我为什么要动？）但多次坚持能累积压力

### NPC 风格影响

| 风格 | 初始耐心 | 基础让步概率 | 让步幅度 | 特点 |
|------|----------|--------------|----------|------|
| **强硬型** | 3 | 15% | 小（5%） | 难推动，但一旦让步说明接近底线 |
| **软弱型** | 5 | 50% | 大（15%） | 容易妥协，但可能记恨 |
| **狡猾型** | 4 | 30% | 中（10%） | Ask 虚高，需多轮试探 |
| **平静型** | 4 | 25% | 中（10%） | 标准基准 |

### 让步概率计算

```
if (玩家让步) {
    让步概率 = 基础概率 + 情境修正
} else if (玩家坚持) {
    让步概率 = 基础概率 × 0.5 + 连续坚持加成 + 情境修正
}
```

**连续坚持加成**：

| 坚持次数 | 加成 |
|----------|------|
| 1 次 | +0% |
| 2 次 | +15% |
| 3 次 | +25% |

**情境修正**：

| 条件 | 概率修正 |
|------|----------|
| 玩家 Offer 接近 NPC 底价（≥90%） | +20% |
| 玩家使用"攻心"技能 | +30% |

**示例**：平静型 NPC（基础 25%）
- 玩家让步：25% 让步概率
- 首次坚持：25% × 0.5 = 12.5%
- 连续坚持 2 次：12.5% + 15% = 27.5%
- 连续坚持 3 次：12.5% + 25% = 37.5%

### "坚持"的博弈

| 策略 | 耐心消耗 | 让步概率 | 策略意义 |
|------|----------|----------|----------|
| 让步（加价） | -1 | 基础概率 | 确定推进，但利润减少 |
| 坚持 | -1 | 基础×0.5+累积 | 概率性推进，保持利润 |

**风险**：坚持消耗耐心但不推进己方价格，若 NPC 连续不让步，可能耐心耗尽时双方差距仍大。

**收益**：成功时 NPC 让步，玩家无需加价；连续坚持有累积概率加成。

### 与现有系统的整合

| 现有机制 | 推拉中的作用 |
|----------|--------------|
| 四档合同 | 不变，仍在开局选择 |
| 商人直觉 | 增加推拉反馈（见下表） |
| 侮辱判定 | 不变，侮辱性报价仍扣双倍耐心 |
| 谈判历史 | 显示双方价格变化轨迹 |
| 技能系统 | "攻心"提升让步概率，"察言观色"显示让步概率档位 |

### 商人直觉文案扩展

| 情境 | 商人直觉文案 |
|------|--------------|
| NPC 让步后 | "他松口了... 还能再压一压。" |
| NPC 拒绝让步 | "他咬死这个价了，再逼可能崩。" |
| 玩家坚持成功 | "僵持有效，他在动摇。" |
| 玩家坚持失败 | "他不为所动，得加点诚意。" |
| 接近成交区 | "差不多了，再让一步就成。" |

### 设计意图

- 增加议价的"谈判感"和策略深度
- 让玩家通过多轮出价试探客户底线
- NPC 风格影响推拉节奏，增加策略多样性
- "坚持"创造风险决策点：消耗耐心换取 NPC 让步概率

### 实现建议

- **framework**: 在 `useNegotiation` 中增加 NPC ask 动态调整逻辑、让步概率计算、坚持检测
- **content**: 补充推拉相关的商人直觉文案矩阵
- **interaction**: 显示 Ask 价格变化动画，可视化双方价格收敛过程

## 人物能力升级系统（三叉融合技能树）

**日期：** 2026-02-03（初稿）→ 2026-02-05（重设计）
**相关系统：** 成长系统、升级系统
**状态：** 设计完成，待实现

### 设计概述

与"典当行升级"（设施层面）并行的成长系统，聚焦玩家角色的个人技能。

**技能树结构（共9个技能）**：
- 3 个纯系技能组（每系 1 主动 + 1 被动）
- 3 个融合技能（两两系融合，各 1 被动）

```
        【灵韵系】
      主动    被动
        \    /
         \  /
    ┌─────●─────┐        ● = 融合技能位置
    │           │
   被动        被动
  /    \     /    \
 /      \   /      \
主动   被动 被动   主动
  【旧影系】   【匠心系】
```

### 精魄系统

| 精魄类型 | 对应系 | 主要获取方式 |
|----------|--------|--------------|
| 匠心精魄 | 匠心系 | 鉴定(+1)、发现特征(+2)、识破赝品/珍品(+5) |
| 旧影精魄 | 旧影系 | 议价成功(+1)、低耐心成交(+3)、用FLAW压价(+2) |

## JACKPOT 特征增加人情声誉

**日期：** 2026-02-05
**相关系统：** 特征系统、声誉系统
**状态：** 待评估

### 描述

使用 JACKPOT 特征后，增加玩家的人情声誉（Humanity）。

### 设计理由

玩家主动告诉客户"这东西比你想的更值钱"，是诚实/善良的表现，应该获得声誉回报。

这让 JACKPOT 的"使用"有了实际意义——玩家面临选择：
1. **不告诉客户**：低价收购获利（经济收益）
2. **告诉客户**：放弃利润但获得人情声誉（声誉收益）

### 设计意图

- 让 JACKPOT 特征的"使用"操作有实际价值
- 创造"利润 vs 道德"的微决策
- 强化人情声誉轴的获取途径

### 待设计

- 具体增加多少人情声誉？
- 是否影响客户后续行为（如回头客、推荐朋友）？
- 是否有特殊对话反馈？

## 关键决策故事设计

**日期：** 2026-02-05
**相关系统：** 事件链系统、声誉系统
**状态：** 待评估

### 背景

声誉归零失败机制已实现（框架层），DSL 已支持三轴声誉修改语法：
- `modify_rep_humanity: <value>`
- `modify_rep_credibility: <value>`
- `modify_rep_innocence: <value>`

但现有故事（emma、zhao、susan）没有合适的位置插入以下关键决策情境。

### 需要设计的故事情境

| 情境 | 选项A | 选项B | 触发机制 |
|------|-------|-------|----------|
| **赃物处理** | 收下：人情+2，清白-3 | 拒绝：清白+1，人情-2 | 客户带赃物上门 |
| **逾期宽限** | 宽限：人情+2，商誉-2 | 严格执行：商誉+2，人情-2 | 物品到期时客户求情 |
| **黑道委托** | 接受：商誉+2，清白-3 | 拒绝/举报：清白+2，商誉-3 | 黑道找上门委托 |
| **警方调查** | 配合：清白+2，人情-2，商誉-1 | 沉默：人情+1，商誉+1，清白-2 | 警方上门调查 |

### 设计要求

每个情境需要：
1. **NPC 角色设计** - 谁带来这个决策？
2. **物品设计** - 是否需要关联物品？
3. **对话设计** - 如何呈现选项？
4. **后续影响** - 选择后的邮件/事件反馈

### 实现方式

通过"物品衍生节点"（DynamicFlows）实现，在 `.story` DSL 中定义。
