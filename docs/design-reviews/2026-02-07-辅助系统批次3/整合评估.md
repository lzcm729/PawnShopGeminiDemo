# 一、店铺升级系统 v1.0

## 1.1 多视角共识问题

### 共识 1：升级成长节奏存在严重的动机空白期

| 视角 | 发现 |
|------|------|
| **动机与强化循环** | 指数增长费用曲线在 Day 10-18 制造"动机真空"，所有低价升级已买完但高价升级遥不可及（发现 2, P0） |
| **数值一致性** | 全升级总费用 $102,800 超过通关目标 $100,000，玩家在通关前只能选择性投资部分升级（发现 3, P1） |
| **玩家体验** | Day 1-7 买不起、Day 8-20 集中买、Day 25+ 没得买的三段式曲线缺乏分形兴趣曲线结构（发现 2, P0） |

**核心问题**：三个视角从不同角度指向同一个结构性缺陷 -- 升级系统的费用曲线与游戏时间轴不匹配。前期资金不足无法启动升级循环，中期集中购买后迅速耗尽目标，后期升级系统变得无关紧要。Sylvester 的叠加强化循环理论要求"始终有一个奖励即将到来"，但当前设计在至少两个时间段出现动机真空。

---

### 共识 2：升级购买缺乏即时反馈和持续存在感

| 视角 | 发现 |
|------|------|
| **动机与强化循环** | 后间升级（储物架/工作台）一旦购买即"消失"于玩家意识，缺乏持续存在感（发现 6, P1） |
| **玩家体验** | 花费 $500-$12,000 的巨款，得到的反馈仅是数字变化，缺乏分层反馈系统（发现 1, P0） |

**核心问题**：升级是玩家的重大决策时刻，但系统在两个层面缺乏反馈 -- 购买瞬间缺乏仪式感（视觉、音效、文案），购买之后缺乏持续的"成长感"提醒。这导致升级从"激动人心的里程碑"退化为"改了一个数字"。

---

### 共识 3：升级系统与道德困境/玩法路线的对齐问题

| 视角 | 发现 |
|------|------|
| **动机与强化循环** | 升级系统鼓励"积累资金"行为，可能暗中偏袒压榨路线，削弱道德选择的两难性（发现 7, P0） |
| **玩家体验** | 五大升级路径之间缺乏有意义的互斥/协同叙事，没有构建"构型身份"（发现 8, P1） |
| **数值一致性** | 所有升级从 Day 1 就可见，缺乏前置条件和策略引导（发现 11, P2） |

**核心问题**：升级系统在资金驱动的设计中可能系统性地奖励"赚更多钱"的行为（高利贷路线更快升级），与游戏核心主题"生存 vs 良心"产生冲突。同时缺乏路线差异化设计，未能将升级投资转化为有个性的"玩法身份"。

---

### 共识 4：维护费决策可能固化为非决策

| 视角 | 发现 |
|------|------|
| **动机与强化循环** | 设施控制面板的每日决策可能陷入"最优解固化"（发现 13, P2） |
| **玩家体验** | 资金充裕时全开，资金紧张时全关，决策退化为非决策（发现 7, P1） |

**核心问题**：设施开关决策的初始设计是优雅的，但如果缺乏足够的环境变量（新闻、客户类型波动），玩家很快会找到固定策略，日常开关变成无脑操作。

# 二、库存物品日志系统 v1.1

## 2.1 多视角共识问题

### 共识 1：日志系统本质是被动阅读，缺乏玩家能动性

| 视角 | 发现 |
|------|------|
| **玩家体验** | 除了展开/折叠外没有任何针对日志内容的行动动词，系统只能"打开和关上"（发现 1, P0） |
| **叙事整合** | 玩家的关键决策（合同利率、送客态度、到期处理）没有在日志中留下痕迹，日志是"NPC的故事"而非"我和NPC的故事"（发现 1, P0） |

**核心问题**：这是三个视角中最具共识性的问题。日志系统是一个精美的"博物馆"，但玩家只是参观者。Rouse 的"玩家想要做，而不是看"原则在此受到最直接的挑战。需要同时增加操作层动词（标注、对比、导航）和内容层反映（记录玩家的选择痕迹），让日志从"被动展馆"变成"互动工作台"。

---

### 共识 2：自然演变日志缺乏感知通道

| 视角 | 发现 |
|------|------|
| **玩家体验** | 演变日志是被动追加的，玩家没有任何提示告诉他"某件物品发生了变化"（发现 2, P0） |
| **叙事整合** | 自然演变是唯一不依赖主动点击就能推动"时间流逝"感知的机制，但设计文档与评估决策存在矛盾（发现 2, P0） |

**核心问题**：自然演变的设计概念很好（物品的静默衰变暗示 NPC 命运），但缺乏让玩家"感知到"变化的通道。如果玩家不知道演变在发生，它就无法产生设计预期的情感效果。建议至少通过轻量级视觉提示（物品图标蒙灰、库存列表小圆点）让变化可感知。

---

### 共识 3：日志与核心玩法和事件链系统缺乏机制性连接

| 视角 | 发现 |
|------|------|
| **玩家体验** | 纯信息终端，无回路。与核心玩法（鉴定、议价、财务决策）没有机制性连接（发现 10, P2） |
| **叙事整合** | 事件链系统的"命运预兆"只在 NPC 对话中呈现，日志系统独立运行，两个系统各自产生叙事碎片但没有交叉引用（发现 5, P1） |

**核心问题**：日志系统是一个纯粹的信息终端 -- 只接收信息，不向外输出。这违反了 Sylvester 的优雅启发"与多个系统互动的机制"。需要至少一条轻量级的机制回路（如日志信息影响议价选项、事件链关键节点向物品日志追加"回响"条目）。

---

### 共识 4：文案情感密度过于均匀，缺乏节奏变化

| 视角 | 发现 |
|------|------|
| **玩家体验** | 文案情感密度均匀，边际效用递减，长期使用产生文案疲劳（发现 7, P1） |
| **叙事整合** | NPC 角色在日志中缺乏内在矛盾的表达，形象单维度（发现 8, P1） |

**核心问题**：日志文案高度依赖文学性描写，所有条目的情感质地相似（都是沉重的叙事笔触），缺乏节奏变化。需要建立 3-4 种日志"语调档位"（事务性/观察性/情感性/戏剧性），并增加角色矛盾描写。

---

### 共识 5：展开/折叠默认显示的信息优先级问题

| 视角 | 发现 |
|------|------|
| **认知负荷** | "最新"和"最重要"不一致时，默认显示可能错过关键信息（发现 6, P1） |
| **叙事整合** | 频繁交易 NPC 最有叙事价值的入库快照被折叠在底部（发现 9, P2） |

**核心问题**：默认显示"最新 1-2 条"的逻辑在叙事意义上不是最优。建议采用"首尾双显"策略 -- 显示最早和最新各一条，让玩家第一眼看到时间跨度的对比。

---

## 2.3 亮点共识（保留）

- **"时间琥珀"概念**（玩家体验+叙事整合双方共识）：Snapshot 机制将 NPC 的瞬时状态永久封存在物品中
- **"叙事碎片容器"系统定位**（认知负荷+叙事整合双方共识）：精准的边界划定大幅降低了认知负荷上限
- **"贴满便利贴的旧档案袋"视觉隐喻**（认知负荷视角）：教科书级别的界面隐喻
- **鉴定发现的讽刺审美**（玩家体验+叙事整合双方共识）："机制即叙事"的典范设计
- **切片叙事的空间叙事**（玩家体验视角）：将时间维度叙事投射到空间维度
- **8个维度中大部分对玩家完全透明**（认知负荷视角）：设计复杂度没有转化为玩家感知复杂度

# 三、日历与财务预测系统 v1.1

## 3.1 多视角共识问题

### 共识 1：不定时小额支出对日历预测可靠性的破坏

| 视角 | 发现 |
|------|------|
| **决策质量** | 不定时支出在日历三类数据源中没有归属，可能导致"日历显示安全"但被突发支出击垮（发现 2, P0） |
| **认知负荷** | 随机支出破坏预测可靠性，"日历没红灯就安全"的心智模型被打破（发现 8, P0） |
| **玩家体验** | 缺乏触发节奏和通知方式，从"增加紧迫感"变成"不公平的惩罚"（发现 7, P0） |

**核心问题**：三个视角一致认为这是本系统最严重的问题。日历系统的核心承诺是"预见性带来的焦虑" -- 如果预见不可靠（随机支出可以无预警地击穿预测），系统的信任基础就崩溃了。三个视角都建议引入"预兆机制" -- 在随机支出发生前至少给予 1 天的预警。

---

### 共识 2：软收入不确定性在界面上完全不可见

| 视角 | 发现 |
|------|------|
| **决策质量** | 预警系统没有区分确定收入和不确定收入，可能导致虚假安全或虚假恐慌（发现 1, P1） |
| **认知负荷** | 玩家把预测余额当作确定真相，回款未到时感到"系统骗了我"（发现 3, P1） |
| **玩家体验** | 软收入显示为实线确定数字，但实际上可能收不回来（发现 3, P0） |

**核心问题**：日历将不同确定性的信息混为一个信号。三个视角都建议用视觉差异化（实线/虚线、深色/浅色）表达回款的可信度等级，让玩家能区分"确定的"和"有条件的"安全。

---

### 共识 3：日历是纯"只读"系统，缺乏行动动词

| 视角 | 发现 |
|------|------|
| **决策质量** | 日历只展示问题但不提供新的行动选项（发现 11, P0） |
| **认知负荷** | 玩家看到红色警告但不知道怎么消除它，缺乏"发现问题到采取行动"的操作路径（发现 10, P1） |
| **玩家体验** | 在 9 个夜间活动竞争中，日历是唯一"零行动动词"的界面（发现 1, P1 & 发现 6, P1） |

**核心问题**：日历是一个报警器而非工具。玩家看到问题后必须退出日历去其他系统操作。需要增加至少 1-2 个行动入口（跳转到物品详情、展示应对方案提示），让日历成为"决策的跳板"。

---

### 共识 4：悬停交互隐藏关键信息，存在心流断裂

| 视角 | 发现 |
|------|------|
| **决策质量** | 缺口金额仅在悬停时显示，在"知道有危机"和"理解严重程度"之间插入了强制非决策交互（发现 5, P0） |
| **认知负荷** | 玩家不一定知道可以悬停查看详情，关键信息获取难度与重要性不匹配（发现 5, P1） |

**核心问题**：两个视角都指出红色警告应默认显示缺口金额，而非隐藏在悬停后面。每一次强制交互都必须包含一个决策，否则就是心流的障碍物。

---

### 共识 5：安全期日历完全沉默，中低压时期体验空白

| 视角 | 发现 |
|------|------|
| **决策质量** | 安全时什么都不显示，剥夺了玩家做长线规划的信息源（发现 7, P1） |
| **玩家体验** | Day 1-3"投资期"缺乏微观钩子，日历在安全期完全空白（发现 2, P1） |
| **认知负荷** | 新玩家首次打开日历可能看到空白网格，不知道系统有什么用（发现 2, P1） |

**核心问题**：危机驱动显示是优雅的设计原则，但被过度执行了。安全期不应完全沉默 -- 至少应显示预期回款标记、到期物品提醒和累积净收入趋势，让日历在非危机时期也保持最低限度的信息价值。

---

## 3.2 各视角独特发现

### 决策质量独特发现

| 编号 | 严重度 | 标题 |

# 四、填充事件系统 v2.0

## 4.1 多视角共识问题

### 共识 1：填充事件与叙事事件的操作层完全同质化

| 视角 | 发现 |
|------|------|
| **玩家体验** | 填充事件完整使用鉴定+议价系统，与叙事客户流程一致，兴趣曲线退化为平坦线（发现 1, P0） |
| **玩家体验** | 填充事件没有专属交互动词，感觉像"阉割版"叙事事件（发现 2, P0） |
| **优雅性** | 填充事件完整复用鉴定/议价系统是好的复用（发现 14, 亮点），但需要操作层差异化 |

**核心问题**：填充事件被定位为兴趣曲线中的"休息点"，但操作密度和认知负荷与"高潮点"完全相同。需要引入"快速交易模式"（简化鉴定+缩短议价）和专属行动动词（快速翻检、拒收推荐）来在手感上兑现差异化承诺。

---

### 共识 2：赎回/续当/绝当结算缺乏玩家能动性和反馈

| 视角 | 发现 |
|------|------|
| **玩家体验** | 到期结算缺乏即时反馈仪式感，微观兴趣曲线的"延迟高潮"缺失（发现 3, P0） |
| **叙事整合** | 赎回/续当/绝当使用纯概率判定，玩家对结果无主动控制权（发现 3, P0） |
| **优雅性** | 续当路径与"一次性交易，干净利落"设计目标直接矛盾，增加不必要的状态复杂度（发现 5, P0） |

**核心问题**：三个视角从不同角度指出后半段生命周期的问题 -- 玩家失去能动性（纯概率决定）、缺乏反馈仪式（结算沉默）、管理负担增加（续当循环）。建议强化因果感知（合同选择影响赎回率）、增加结算反馈仪式、简化或取消填充客户的续当路径。

---

### 共识 3：出场顺序过于固定可预测

| 视角 | 发现 |
|------|------|
| **玩家体验** | 固定模式（叙事优先+填充递增）在多次经历后丧失新鲜感（发现 5, P1） |
| **叙事整合** | 可预测的顺序消除了"今天会遇到谁"的期待感（发现 7, P2） |
| **优雅性** | 固定模板是"编排"逻辑，不是"涌现"逻辑，应由简单规则产生（发现 8, P1） |

**核心问题**：三个视角都建议增加 20-30% 的随机扰动，打破完全可预测的出场节奏。

---

### 共识 4：赎回率调整规则过于复杂，玩家无法推断

| 视角 | 发现 |
|------|------|
| **玩家体验** | 赎回概率对玩家完全不透明，"活当vs死当"策略退化为盲猜（发现 11, P1） |
| **叙事整合** | 缺少具体机制设计让玩家推断赎回意愿（发现隐含在发现 3 分析中） |
| **优雅性** | 三层赎回率修正叠加（基础+合同+6条情境规则），核心决策依据不可预测（发现 7, P0） |

**核心问题**：赎回率是填充事件最核心的决策依据（活当还是死当路径），但玩家面对的是一个黑箱。需要压缩修正层次（主轴+单一修正），并通过可感知的线索（对话、行为、直觉提示）让玩家能做出有信息支撑的判断。

---

### 共识 5：中期重复疲劳风险

| 视角 | 发现 |
|------|------|
| **玩家体验** | 游戏中期（Day 10-20）熟练掌握流程后，填充事件退化为机械性操作，缺乏额外强化循环（发现 4, P0） |
| **叙事整合** | 填充客户的"一次性"性质限制了涌现叙事，无法验证脑补（发现 8, P1） |

**核心问题**：填充事件占 60-80% 的游戏时间，但只有一个强化循环（金钱收益）。需要叠加 2-3 个额外循环（鉴定精度追踪、稀有遭遇、回头客机制）来对抗中期疲劳。

# 五、跨系统共性问题

通过对四个系统的交叉比对，以下问题在多个系统中反复出现：

### 跨系统共性 1：被动阅读/只读系统泛滥

| 系统 | 表现 |
|------|------|
| 库存物品日志 | 纯被动阅读，无操作动词 |
| 日历与财务预测 | 纯只读仪表盘，无行动入口 |
| 店铺升级（预约板） | 信息展示为主，缺乏交互路径 |
| 填充事件 | 缺少专属行动动词 |

**共性根因**：辅助系统普遍被设计为"信息展示器"而非"决策工具"。需要系统性地为每个辅助界面增加至少 1-2 个行动入口，让信息直接连接到行动。

### 跨系统共性 2：中后期动机空白

| 系统 | 表现 |
|------|------|
| 店铺升级 | Day 20+ 升级系统变得无关紧要 |
| 库存物品日志 | 游戏中后期玩家停止访问日志 |
| 日历与财务预测 | 安全期日历完全沉默 |
| 填充事件 | Day 10-20 后退化为机械操作 |

**共性根因**：所有辅助系统都缺乏长期动机维持机制。需要为中后期设计新的强化循环或内容注入（升级的终局价值、日志的机制回路、日历的长期目标追踪、填充事件的额外循环）。

### 跨系统共性 3：反馈仪式感缺失

| 系统 | 表现 |
|------|------|
| 店铺升级 | 升级购买无视觉/音效/文案庆祝 |
| 日历与财务预测 | Day 7 审判日结算无仪式感 |
| 填充事件 | 赎回/续当/绝当结算无反馈设计 |

**共性根因**：重大决策时刻的感官反馈被系统性地忽略。Schell 的 Juiciness 透镜要求"最大输出 from 最小输入"，但当前设计中关键时刻的反馈密度过低。

### 跨系统共性 4：文档与代码/跨文档的一致性问题

| 系统 | 表现 |
|------|------|
| 店铺升级 | 光谱仪公式文档与代码不一致；文档缺失黑市联络网；总投资额估算偏离实际 |
| 日历与财务预测 | 维护费扣除时机跨文档不一致 |
| 填充事件 | 续当路径与"一次性交易"设计目标矛盾 |

**共性根因**：随着系统间关联增多，文档间的交叉引用和一致性维护变得困难。建议建立跨文档的数值交叉验证机制。

## 核心发现总结

**四个系统的共同优势**在于设计理念层面的成熟：店铺升级的柜台/后间二分法、日志系统的"时间琥珀"概念、日历的"预见性焦虑"、填充事件的 Apophenia 哲学 -- 这些都展现了设计团队对游戏设计理论的深入理解和独到应用。

**四个系统的共同短板**在于"最后一公里"的体验落地：
1. **被动性过强** -- 辅助系统普遍是"只能看不能做"的信息展示器
2. **反馈仪式缺失** -- 重大决策时刻的感官反馈被系统性忽略
3. **中后期动机空白** -- 所有系统都缺乏长期动机维持机制
4. **文档一致性** -- 跨文档和文档-代码间的数值/逻辑不一致需要清理
