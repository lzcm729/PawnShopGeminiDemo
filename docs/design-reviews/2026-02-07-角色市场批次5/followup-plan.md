## 四、执行计划

### 推荐执行顺序

```
阶段 A: Interaction (UI) — 可并行
├── UI-1 修行面板 (最大，独立)
├── UI-2 洞察结果重构 (中等，独立)
└── UI-3~UI-8 (小任务，可打包)

阶段 B: Content (数据填充) — 依赖 UI 完成后的结构
├── CT-1 行为描写扩展
├── CT-2 NPC声誉文案
├── CT-3 镜鉴警告文案
└── CT-4 道德回声文案

阶段 C: QA (验证) — 全部完成后
├── QA-1 洞察系统
├── QA-2 人物能力系统
├── QA-3 黑市系统
└── QA-4 事件链+声誉
```

### 批次建议

| 批次 | 任务 | Agent | 预估工作量 |
|------|------|-------|-----------|
| **A-1** | UI-1 修行面板 | Interaction | 大 (新面板) |
| **A-2** | UI-2 洞察重构 + UI-3~UI-8 打包 | Interaction | 中 |
| **B-1** | CT-1~CT-4 全部 | Content | 中 |
| **C-1** | QA-1~QA-4 逐系统 | qa-tester | 中 |

### 是否可以并行

- **A-1 和 A-2 可并行**: 修行面板和洞察/黑市UI互不依赖
- **B 依赖 A**: 文案填充需要知道 UI 结构（但 CT-1 行为描写可以提前做）
- **C 依赖 A+B**: QA 需要 UI 可交互才能验证
