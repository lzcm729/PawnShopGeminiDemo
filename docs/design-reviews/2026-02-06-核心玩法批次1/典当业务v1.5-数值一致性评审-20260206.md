## 发现列表

### 1. 强制违约赔偿基数：设计文档 vs 经济参数 vs 代码实现三方不一致

**问题**: 强制违约赔偿金的计算基数在三个来源中存在矛盾。

**分析**:

| 来源 | 赔偿基数 | 赔偿公式 |
|------|----------|----------|
| 典当业务 v1.5 (版本历史) | **当金 (principal)** | 200% x 当金 |
| 经济参数 v1.0 (第72行) | **估值** | "违约赔偿倍数 200%"，说明列为"强制违约需赔偿估值的2倍" |
| 代码 expiryReducer.ts (第57行) | **valuation** | `Math.ceil(item.pawnInfo.valuation * 2)` |
| 代码 blackmarketService.ts (第285行) | **pawnAmount** | `Math.ceil(item.pawnAmount * 2)` |

v1.5 版本历史明确写道"赔偿基数明确为'当金'（非估值）"，但:

1. **经济参数文档未同步更新**，仍写"赔偿估值的2倍"。
2. **expiryReducer.ts 使用 `valuation * 2`**（估值基数），而 **blackmarketService.ts 使用 `pawnAmount * 2`**（当金基数）。同一个游戏中，拒绝赎回和黑市违约出售走的是不同的赔偿基数。

数值差异巨大。假设一个物品 realValue=$5000, perceivedValue(valuation)=$4000, pawnAmount=$2000:
- 按当金: 赔偿 = $2000 x 2 = $4,000
- 按估值: 赔偿 = $4000 x 2 = $8,000

这导致两个问题:(a) 两条代码路径赔偿金额可能差一倍; (b) 场景三"贪婪捕食"中写的"赔偿金只需$7,000"来自当金$3,500 x 2，但如果走 expiryReducer 的估值路径，赔偿可能远高于此。

**建议**: 统一为"当金 x 2"（与 v1.5 版本历史的决策一致）。同步更新:
- 经济参数文档第72行："违约赔偿倍数 200%"说明改为"当金的200%"
- expiryReducer.ts 第57行: 将 `item.pawnInfo.valuation` 改为 `item.pawnInfo.principal`
- 确认 blackmarketService.ts 已使用正确基数

**严重程度**: 高。这是核心经济机制的基数不一致，直接影响玩家决策和游戏平衡。

### 2. 强制违约声誉惩罚：设计文档 vs 经济参数严重矛盾

**问题**: 强制违约对声誉的影响在设计文档和经济参数文档中差异巨大。

**分析**:

| 来源 | HUMANITY | CREDIBILITY | INNOCENCE/UNDERWORLD |
|------|----------|-------------|----------------------|
| 典当业务 v1.5 (E节) | -15 | -10 | -5 (Innocence) |
| 经济参数 v1.0 (第141-148行) | **-30** | **-20** | **+10 (Underworld)** |
| 代码 expiryReducer.ts (第59-63行) | -15 | -10 | -5 (Innocence) |

差异:
- HUMANITY: -15 vs -30（差一倍）
- CREDIBILITY: -10 vs -20（差一倍）
- 第三维度完全不同: 典当业务+代码用 Innocence -5; 经济参数用 Underworld +10

这里还涉及一个概念性差异: 经济参数用的是旧的三轴体系(Humanity/Credibility/Underworld)，而 game.toml 和代码使用的是新的三轴体系(Humanity/Credibility/Innocence)。经济参数文档整体滞后。

**建议**: 以典当业务 v1.5 + 代码实现为准(人情-15, 商誉-10, 清白-5)，更新经济参数文档。同时将经济参数中的 Underworld 术语统一为 Innocence（如有全局决定保留 Underworld 则另议）。

**严重程度**: 高。数值权威文档与实现文档矛盾，且差异幅度足以改变玩家策略。

### 3. 黑市违约出售(breach_discovered)的声誉惩罚过低

**问题**: 玩家在黑市提前出售 ACTIVE 物品（违约出售）后，当 NPC 返回赎回时触发的 `breach_discovered` 事件，声誉惩罚仅为 HUMANITY -3, CREDIBILITY -1。

**分析**:

对比两种违约路径:

| 违约方式 | 操作 | HUMANITY | CREDIBILITY | INNOCENCE |
|----------|------|----------|-------------|-----------|
| 强制违约(redeem_refuse) | 当面拒绝赎回 | -15 | -10 | -5 |
| 黑市违约(breach_discovered) | 偷偷卖了，被发现 | **-3** | **-1** | 0 |

黑市违约在道德上**更恶劣**（背着客户卖掉他的东西），但声誉惩罚只有强制违约的 1/5 到 1/10。这创造了一个明显的漏洞: 理性玩家永远应该选择黑市违约而非当面拒绝赎回，因为经济成本相同(200% 当金)但声誉成本几乎可忽略。

经济计算对比（假设当金 $2000）:
- 强制违约: 赔偿 $4000，声誉总损失 30 点
- 黑市违约: 赔偿 $4000（如果 NPC 返回），声誉总损失 4 点，**且卖出物品获得额外收入**

黑市违约严格优于强制违约，甚至可能净赚。

**建议**: 将 breach_discovered 的声誉惩罚提升至与 redeem_refuse 同级或更高。建议: HUMANITY -15 至 -20, CREDIBILITY -10 至 -15, INNOCENCE -5 至 -10。理由: 偷卖比当面拒绝更严重。

**严重程度**: 高。存在明显的策略漏洞，理性玩家会完全规避强制违约路径。

### 4. 续当利息公式与包干制的交互需要明确

**问题**: 续当（renew_accept）时的利息计算与初始包干制利息之间的关系不够清晰。

**分析**:

代码中续当利息计算（expiryReducer.ts 第74行）:
```
interest = Math.ceil(item.pawnInfo.principal * item.pawnInfo.interestRate)
```

这里没有乘以天数/7，即续当利息 = principal x rate x 1（一个周期，7天）。

而初始合同利息公式（interest.ts 第18行）:
```
interest = Math.ceil(principal * rate * (days / 7))
```

初始合同默认 termDays = 7，所以初始利息也是 principal x rate x 1。

这意味着续当一次，玩家收取的利息**等于初始合同全额利息**。举例:
- 当金 $2000，利率 10%，期限 7 天
- 初始利息 = $2000 x 0.10 x 1 = $200
- 续当利息 = $2000 x 0.10 = $200（相同）

从设计角度这是合理的（每周收一次利息），但设计文档中未明确说明续当利息等于初始利息这一点。文档 F 节"同意续当"只写"+当期利息"，没有给出计算示例。

然而，如果未来支持非7天的初始期限，两个公式会产生分歧。设计文档需要明确: **续当固定按7天计息，无论初始合同期限是多少**。

**建议**: 在设计文档 F 节"续当"描述中添加明确的公式: `续当利息 = 当金 x 利率`（即固定按一个7天周期计算）。同时确认代码中的 extensionDays 默认值 7 是否需要暴露为可配置参数。

**严重程度**: 低。当前数值自洽，但文档缺乏明确性，可能在扩展时引发歧义。

### 5. 绝当自动变现比例与黑市系统的关系未厘清

**问题**: 经济参数文档定义"绝当变现比例 80%"（realValue x 0.8），但鉴定系统引入了黑市波动机制(方向C')，两者可能冲突。

**分析**:

存在两个变现路径:

| 路径 | 变现价格 | 来源 |
|------|----------|------|
| 到期结算 noshow_sell | `realValue x 0.8` | expiryReducer.ts 第109行 |
| 黑市手动出售 | `realValue x 市场系数 x 波动偏移 x 精度修正` | 鉴定系统 C' |

问题: 如果物品绝当后进入 FORFEIT 状态，玩家可以选择:
(a) 在到期结算节点直接卖出 = 固定 80%
(b) 保留（noshow_keep），之后去黑市卖 = 波动价格

根据鉴定系统 C' 的数值:
- uncertainty 0.05 时: 期望波动 0%，即黑市基准价 = 日基准系数（可能高于或低于 80%）
- uncertainty 0.30 时: 期望偏移 -10%，波动范围 [-30%, +10%]

设计文档没有说明"80% 快速变现"是否应该与黑市系统联动。如果 80% 是硬编码的固定值，那么高 uncertainty 物品在到期结算时获得固定 80%（可能高于黑市期望值），而低 uncertainty 物品在黑市可能卖出更高价。这创造了一个反直觉的策略: **不鉴定的物品反而应该在到期结算时卖出，而鉴定充分的物品应该留到黑市。**

**建议**: 明确设计意图:
- 方案A: 到期结算的变现也走黑市系统（统一定价），不再使用固定 80%
- 方案B: 保留 80% 作为"快速变现折扣价"，但在设计文档中明确说明这是便利性折扣，玩家可以选择保留到黑市获取更好价格

**严重程度**: 中。涉及两个系统的经济交互，可能产生反直觉的最优策略。

### 6. 每日客户数与经济压力的平衡分析

**问题**: game.toml 中 max_customers_per_day = 4，但经济参数文档仍写"每日最大客户数 1"。更关键的是，每日收入能否覆盖周期性支出。

**分析**:

**固定支出（每7天）**:
- 日常开支: $50/天 x 7 = $350
- 医药费: $1,000
- 7天总支出: **$1,350**

**典当收入估算（每7天）**:

假设每日 4 客户，7天共 28 笔交易。假设平均物品 realValue=$800，平均当金=$500（约 realValue 的 62.5%）:

| 利率档位 | 利息/笔 | 假设比例 | 周利息收入 |
|----------|---------|----------|------------|
| 0% 慈善 | $0 | 10% (2.8笔) | $0 |
| 5% 援助 | $25 | 30% (8.4笔) | $210 |
| 10% 标准 | $50 | 50% (14笔) | $700 |
| 20% 高险 | $100 | 10% (2.8笔) | $280 |
| **合计** | | | **$1,190** |

**注意**: 这里的 $1,190 是假设**所有客户都按时赎回**的理论最大利息收入。实际上:
- 部分客户不会赎回（绝当），利息无法收取
- 绝当物品变现 = realValue x 0.8 = $640，但当金已支出 $500，净收益仅 $140
- 当金本身是资金占用，不是收入

**周净现金流估算**:
- 利息收入: ~$1,190（乐观）
- 绝当变现净收益: ~$140/件（假设30%绝当率，约 8.4 件 x $140 = $1,176）
- 赎回回笼本金: 不计为收入（只是资金回流）
- 总支出: $1,350

在乐观假设下，周净收入约 $1,016（$1,190 + $1,176 - $1,350 = $1,016）。但这需要占用大量营运资金（28笔 x $500 = $14,000 的当金需要周转）。初始资金只有 $10,000，第一周就会面临资金断裂风险。

**达成目标的时间**: $100,000 / $1,016/周 = **约 98 周 = 686天**。这远超合理游戏时长。

即使在极端高利贷模式（全部20%）: 周利息 = 28 x $100 = $2,800 - $1,350 = $1,450/周，也需要 **69 周 = 483天**。

**建议**: 这个粗略模型暴露了几个需要关注的点:
1. 经济参数文档中"每日最大客户数 1"需要更新为 4
2. 医药费 $1,000/周 可能需要根据最终收入模型调整
3. 手术费 $100,000 目标需要结合绝当变现利润（非利息）来达成，设计文档应说明主要收入来源是什么
4. 初始资金 $10,000 是否足够支撑前几周的当金周转

**严重程度**: 中。经济参数文档滞后，且整体经济模型的可行性需要进一步数值验证。

### 7. 利息公式中的"期限"含义需要澄清

**问题**: 利息公式 `利息 = 本金 x 利率 x 期限(天) / 7` 在默认 7 天期限下结果正确，但公式本身的含义与"包干制"存在微妙矛盾。

**分析**:

公式: `interest = principal x rate x (days / 7)`

其中 rate 是**周利率**（如 10%）。当 days=7 时:
- interest = principal x rate x 1 = principal x rate

这意味着 rate 实质上是**每合同期的利率**（而非年化利率或日利率）。

但如果未来扩展支持非 7 天期限（如 14 天合同），公式会产生:
- interest = principal x rate x 2

即 14 天合同的利息是 7 天合同的**两倍**。这是否是设计意图？包干制的核心承诺是"利息在签约时锁定"，但锁定的利率是周利率还是合同期利率？

当前代码中 termDays 是由何处决定的？续当时 extensionDays 默认 7。如果所有合同都是 7 天，那这个公式没有问题。但设计文档未明确限制合同期限只能是 7 天。

**建议**: 在设计文档或经济参数中明确:
- 所有合同的标准期限为 7 天（如果是这样的话）
- 或者，如果支持不同期限，明确 rate 的含义（周利率 vs 合同期利率）

**严重程度**: 低。当前所有合同均为 7 天期限，暂无实际问题。

### 8. 赎回声誉奖励可能创造"刷声誉"漏洞

**问题**: 设计文档 F 节定义赎回时声誉奖励为 HUMANITY +3, CREDIBILITY +2。这意味着每次正常赎回交易无条件获得 +5 总声誉。

**分析**:

如果玩家选择 0% 慈善利率:
- 签约时: HUMANITY +5（慈善交易奖励）
- 赎回时: HUMANITY +3, CREDIBILITY +2
- 单笔交易总声誉收益: HUMANITY +8, CREDIBILITY +2 = **总计 +10**

每天 4 客户，全部 0% 慈善:
- 每天: HUMANITY +32, CREDIBILITY +8
- 一周: HUMANITY +224, CREDIBILITY +56

声誉上限为 100。这意味着玩家只需 **3 天** 即可将 HUMANITY 从 50 刷到 100（上限），CREDIBILITY 约 7 天到上限。

虽然慈善利率意味着零利息收入，但声誉回报极高且无风险。如果声誉解锁任何有价值的内容（事件、商业优惠等），这会成为被利用的策略。

同时，高利贷档位的声誉惩罚（HUMANITY -3, CREDIBILITY -2, UNDERWORLD +2 = 净 -3）远小于慈善的收益（+10/笔），创造了不对称: 玩家可以先大量做慈善刷声誉，再切换到高利贷赚钱，净声誉变化仍为正。

**建议**:
1. 考虑赎回声誉奖励是否需要与合同利率挂钩（0% 赎回给 +5 合理，20% 赎回给 +1 或 +0）
2. 或增加声誉获取的递减收益（连续多笔同类交易声誉增长递减）
3. 确保声誉变化速度与游戏节奏匹配

**严重程度**: 中。在 max_customers_per_day=4 的设定下，声誉增长速度过快，可能破坏声誉系统的权衡意义。

### 9. 赎回 vs 续当场景缺少NPC支付能力的经济模型

**问题**: 设计文档 F 节描述"赎回"和"续当"取决于 NPC 的经济状况，但未定义 NPC 经济状况如何影响赎回能力。

**分析**:

赎金 = 当金 + 利息 = principal x (1 + rate)

示例: 当金 $2000, 利率 10% → 赎金 = $2,200

NPC 是否能赎回取决于其"剩余资金"（由 SimRules 模拟），但设计文档没有定义:
1. NPC 赎回时需要多少现金？是赎金全额还是可以部分？
2. 高利贷 (20%) 时赎金 = $2,400 vs 慈善 (0%) 时赎金 = $2,000——利率选择如何影响 NPC 赎回概率？
3. 续当时 NPC 需要支付多少？文档写"+当期利息"（$200 at 10%），这是否从 NPC 资金中扣除？

这意味着玩家选择高利贷不仅赚更多利息，还可能**降低 NPC 赎回概率**（因为赎金更高），导致绝当——这是一个重要的经济反馈循环，但设计文档未明确量化。

**建议**: 在设计文档中明确:
- 利率选择如何影响 NPC 赎回概率（建议: 赎金占 NPC 剩余资金的比例影响赎回概率）
- 续当时 NPC 支付的利息是否影响其后续赎回能力
- 这是核心的"利率-赎回概率"经济反馈循环，应在典当业务文档中明确

**严重程度**: 中。这是核心博弈点（高利率 = 高利息但低赎回概率），但缺乏数值定义。

### 10. 场景三"贪婪捕食"中的数值与系统规则存在不自洽

**问题**: 设计文档场景三描述"赔偿金只需 $7,000"，但按当金 $3,500 x 200% = $7,000 计算，这要求老兵的当金为 $3,500。然而老兵在场景中"手里的 $3,500 赎金"暗示赎金=当金+利息=$3,500，意味着当金低于 $3,500。

**分析**:

如果赎金 = $3,500:
- 慈善 (0%): 当金 = $3,500, 利息 = $0 → 赎金 = $3,500
- 标准 (10%): 当金 = $3,182, 利息 = $318 → 赎金 = $3,500
- 高利贷 (20%): 当金 = $2,917, 利息 = $583 → 赎金 = $3,500

赔偿金（按当金 x 200%）:
- 慈善: $3,500 x 2 = $7,000
- 标准: $3,182 x 2 = $6,364
- 高利贷: $2,917 x 2 = $5,834

只有在 0% 慈善利率下赔偿金才恰好是 $7,000。但一个"贪婪捕食"场景中，玩家给老兵 0% 慈善利率是非常不自然的叙事选择。

另外，勋章值 $50,000 但当金只有 $3,500，意味着当金仅为 realValue 的 7%。设计文档说"当金 < 估价"是硬约束，但估价(perceivedValue)和真实价值(realValue)可能差异很大。如果 perceivedValue 也是 $50,000（玩家鉴定后已知），那当金 $3,500 占估价 7% 是否合理？

这个场景更像是为了戏剧性而设计的数值示例，而非严格的系统推演。

**建议**: 调整场景三的数值使其与系统规则完全自洽。例如: 当金 $3,000（约 perceivedValue $4,000 的 75%），利率 10%，赎金 = $3,300，赔偿金 = $6,000。然后通过鉴定发现 realValue = $50,000。这样数值链完整且合理。

**严重程度**: 低。示例场景不影响实际系统运行，但作为设计文档应保持数值自洽。

### 11. 初始声誉值：经济参数 vs game.toml 不一致

**问题**: 初始声誉值在两个数据源中不同。

**分析**:

| 维度 | 经济参数文档 | game.toml (代码实际使用) |
|------|------------|------------------------|
| Humanity | 30 | **50** |
| Credibility | 20 | **50** |
| Underworld/Innocence | 5 | **50** |

game.toml 将三轴初始值统一设为 50（中立起点），而经济参数文档的初始值不对称（人情最高30，商誉20，黑道最低5）。

代码通过 `config.ts` 读取 game.toml 的值，因此实际游戏使用的是 50/50/50。经济参数文档的 30/20/5 已过时。

此外，经济参数使用 "Underworld（黑道）" 而 game.toml 使用 "Innocence（清白）"，这是两个**语义相反**的概念（黑道高=坏，清白高=好），不仅是命名变更，可能涉及数值方向反转。

**建议**: 更新经济参数文档的初始声誉值为 50/50/50，并将"黑道(Underworld)"统一为"清白(Innocence)"，同步修正所有声誉变化的方向（原 Underworld +X 应变为 Innocence -X）。

**严重程度**: 中。经济参数文档是声明的"权威数值来源"，但实际已严重滞后。

### 12. 续当声誉变化不对称可能被利用

**问题**: 同意续当 HUMANITY +5，拒绝续当 HUMANITY -10。不对称比为 1:2。

**分析**:

这意味着:
- 同意 2 次续当 (+10) 然后拒绝 1 次 (-10) = 净 0
- 但每次续当玩家收取利息（纯收入），只有最后一次拒绝有声誉惩罚

策略: 反复续当收利息，直到积累足够声誉缓冲后拒绝。以标准 10% 利率、当金 $2000 为例:
- 续当 3 次: 收入 $200 x 3 = $600, HUMANITY +15
- 最后拒绝: HUMANITY -10
- 净结果: 收入 $600, HUMANITY +5

每次续当周期 7 天，21 天内净赚 $600 且声誉为正。而物品在这 21 天内持续占用库存位但不影响当金（当金已在初始交易时支出）。

问题在于: 拒绝续当的惩罚 (-10) 不足以抵消多次续当的累积收益。如果 NPC 持续请求续当（取决于 SimRules），玩家会无脑同意直到声誉缓冲足够。

**建议**: 考虑续当次数递增声誉变化:
- 第1次续当: HUMANITY +5
- 第2次续当: HUMANITY +3（递减）
- 第3次续当: HUMANITY +1
- 拒绝续当: HUMANITY -10（保持不变）

或者: 续当次数影响拒绝惩罚的严重程度（续当越多次后拒绝，惩罚越重，因为"给了希望又夺走"更残忍）。

**严重程度**: 低。在实际游戏中，续当次数可能受 NPC 经济状况限制，但理论上存在利用空间。

### 13. "提前出售"ACTIVE物品缺少设计文档中的声誉惩罚

**问题**: 设计文档 C 节定义"违约出售"（提前卖掉未到期物品）是黑暗选项，代价应"高昂"，但代码中黑市出售 ACTIVE 物品时的即时声誉惩罚为零。

**分析**:

代码路径:
1. 黑市出售 ACTIVE 物品 (blackmarketService.ts): 标记 `breachSaleDay`，**无即时声誉变化**
2. NPC 返回赎回时 (expiryReducer.ts, breach_discovered): HUMANITY -3, CREDIBILITY -1

这意味着:
- 如果 NPC 是 NO_SHOW（不会返回），玩家**零声誉惩罚**地违约出售了物品
- 设计文档 C 节写"代价高昂"但实际上只有当 NPC 返回时才有惩罚，且惩罚极低（见发现 #3）

**建议**: 在黑市出售 ACTIVE 物品时应有即时声誉惩罚（独立于 NPC 是否返回），因为**玩家知道自己在违约**。建议: 出售时即时扣除 INNOCENCE -5（知法犯法），NPC 返回时再扣 HUMANITY -15, CREDIBILITY -10（被揭露的代价）。

**严重程度**: 中。配合发现 #3，黑市违约路径整体缺乏足够的惩罚机制。

## 亮点

### A. 包干制利息设计

这是本系统最出色的经济设计。通过将利息锁定为一次性包干费用而非按天计算，巧妙消除了"玩家利益 vs NPC幸福"的经典对立。从数值角度看:
- 提前赎回: 玩家获得相同利息但资金周转更快，等效年化收益率提高
- 延期赎回: 玩家利息不变但资金占用更久，等效年化收益率降低
- 这创造了自然的"希望客户早点赎回"的经济激励，与情感体验完美对齐

### B. 强制违约的经济门槛设计（以当金为基数后）

以当金而非估值为赔偿基数的决策在经济上更优雅。因为当金是玩家已知的确定数字（自己报的价），而估值可能在鉴定后大幅变化。这让玩家在签约时就能预估违约成本，使"贪婪捕食"策略成为**可计划的**决策而非赌博。

### C. 到期结算的三场景分支（REDEEM/RENEW/NO_SHOW）

设计清晰，每个场景都有独特的经济计算和声誉影响。特别是"未现身"自动绝当的设计减少了不必要的决策节点，让玩家注意力集中在真正有意义的选择上。

## 总体评价

典当业务系统 v1.5 的**设计逻辑**非常扎实，核心机制（包干制、契约/违约、状态流转）在概念层面是优秀的。然而从**数值一致性**角度存在较多问题:

1. **跨文档数值矛盾严重**: 经济参数文档（声明为"权威数值来源"）与典当业务文档、代码实现之间存在至少 3 处重大不一致（赔偿基数、声誉惩罚值、初始声誉值、声誉轴命名）。建议将经济参数文档作为最高优先级同步目标。

2. **违约路径经济激励不对齐**: 黑市违约 vs 强制违约的声誉惩罚差异达 5-10 倍，创造了明显的策略漏洞。这需要设计层面的再平衡。

3. **宏观经济可行性需要验证**: 初步估算显示，在当前参数下达成 $100,000 手术费目标可能需要数百游戏日，需要结合绝当变现、黑市交易等非利息收入来源进行完整的经济模型验证。

**优先级建议**:
- 立即处理: 发现 #1（赔偿基数三方不一致）、#2（声誉惩罚两文档矛盾）、#3（黑市违约惩罚过低）
- 近期处理: #5（绝当变现与黑市关系）、#6（经济参数文档更新）、#11（初始声誉更新）
- 后续迭代: #8（声誉刷取速度）、#9（NPC赎回经济模型）、#12（续当声誉递减）

*评审人: Game Designer Agent (数值一致性与经济平衡视角)*
