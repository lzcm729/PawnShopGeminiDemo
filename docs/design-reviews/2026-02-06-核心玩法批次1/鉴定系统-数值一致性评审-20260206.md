## 发现列表

### 1. 事件概率分布不一致：代码与设计文档有偏差

**问题**：设计文档 2.H 节定义了四种鉴定意外事件的概率（灵光一闪 10%、鉴定失误 5%、客户不耐烦 10%、意外发现 5%），但代码实现 (`systems/items/utils.ts` `rollAppraisalEvent`) 中的概率分布逻辑与文档有结构性冲突。

**分析**：

代码中的判定逻辑是顺序互斥的：
```
roll < 0.05 且 uncertainty < 0.15  --> MISHAP (5%)
roll 在 [0.05, 0.15) 且 count >= 2 --> IMPATIENT (10%)
roll 在 [0.15, 0.20)               --> LUCKY_FIND (5%)
其余                                --> NORMAL (80%)
```

这意味着：
- **灵光一闪完全不在 `rollAppraisalEvent` 中**，它在 `useAppraisal.ts` 中独立判定 (`Math.random() < 0.10`)。这不是问题本身，但导致灵光一闪与其他事件**不互斥**——文档 2.H 节明确写"与鉴定失误互斥"，但代码中两者使用不同的随机掷骰，理论上可以同时触发。
- 当 `uncertainty >= 0.15` 时，MISHAP 永远不触发。这与文档"仅当不确定度已较低时触发"一致，但阈值 0.15 未在设计文档中明确标注。
- 当 `appraisalCount < 2` 时，IMPATIENT 永远不触发，此区间的 10% 概率变成了 NORMAL。

**严重程度**：中

**建议**：
1. 在设计文档 2.H 节中明确 MISHAP 的 uncertainty 阈值（< 0.15），与代码对齐。
2. 明确"灵光一闪"与其他事件的互斥实现方式。当前代码使用两个独立 `Math.random()` 掷骰，需要决定：是同一掷骰（真正互斥）还是独立掷骰（可叠加）。如果互斥，建议合并为单一掷骰表。
3. 补充说明：当条件不满足（如首次鉴定）时，事件概率如何重新分配。

### 2. "灵光一闪"与特征发现的交互规则在代码中未完整实现

**问题**：设计文档 2.H 节末尾有一段关键交互规则："若同一次鉴定同时触发'灵光一闪'和特征发现（FAKE/JACKPOT），特征发现优先（uncertainty 直接降至 0.10），灵光一闪的额外收窄不叠加。"

**分析**：

查看 `useAppraisal.ts` 代码第 100-110 行和第 163-175 行：
```typescript
// 先计算 breakthrough
isBreakthrough = Math.random() < 0.10;
const shrinkFactor = isBreakthrough ? 0.60 : 0.85;
newUncertainty = Math.max(0.05, newUncertainty * shrinkFactor);

// ... 后面发现 FAKE/JACKPOT 时:
if (discoveredFakeOrJackpot) {
    newUncertainty = 0.1;  // 直接覆盖
}
```

FAKE/JACKPOT 发现后确实把 uncertainty 覆盖为 0.10，所以最终结果是正确的。但存在一个微妙问题：**代码先执行了灵光一闪的 x0.60 收窄，然后又被 FAKE/JACKPOT 覆盖为 0.10**。如果灵光一闪把 uncertainty 压到了 0.05（例如 uncertainty 已经很低时），最终却被"提升"到 0.10——这违背了直觉（灵光一闪的效果反而"变差"了）。

具体场景：uncertainty = 0.12 时触发灵光一闪 (x0.60 = 0.072)，同时发现 FAKE，被覆盖为 0.10。玩家本应获得 0.072 的精度，但因为 FAKE 覆盖变成了 0.10，反而更高。

**严重程度**：低（边缘场景，且 0.10 vs 0.072 的精度收益差异在连续函数模型中影响有限）

**建议**：
在设计文档中补充明确规则：FAKE/JACKPOT 发现后 uncertainty = min(当前 uncertainty, 0.10)，而非固定设为 0.10。这样灵光一闪的效果在任何场景下都不会被"反向惩罚"。

### 4. 连续函数模型的 normalize 基准点 (u=0.18) 与实际鉴定次数不完全对应

**问题**：文档 3.1 节的数值参考表中，u=0.18 标注为"3 次鉴定"，normalize=0.52，对应修正系数约为基准值（x1.00）。但实际鉴定衰减计算存在偏差。

**分析**：

初始 uncertainty = 0.30，每次乘 0.85：
- 1 次：0.30 x 0.85 = 0.255
- 2 次：0.255 x 0.85 = 0.2168
- 3 次：0.2168 x 0.85 = 0.1842
- 4 次：0.1842 x 0.85 = 0.1566
- 5 次：0.1566 x 0.85 = 0.1331

u=0.18 确实约为 3 次后的值 (0.184)，这是正确的。但 normalize(0.184) = (0.184 - 0.05) / 0.25 = 0.536，对应：
- 开价修正 = lerp(0.92, 1.08, 0.536) = 0.92 + 0.16 x 0.536 = 1.006
- 侮辱修正 = lerp(0.85, 1.10, 0.536) = 0.85 + 0.25 x 0.536 = 0.984
- 让步乘数 = lerp(1.30, 0.70, 0.536) = 1.30 - 0.60 x 0.536 = 0.978

文档中 u=0.18 的数值列为 "开价 x1.00, 侮辱 x1.00, 让步 x0.97"。开价修正实际应为 x1.006（而非精确 x1.00），侮辱修正实际应为 x0.984（而非 x1.00）。差异虽小（< 1%），但"约 3 次鉴定即达基准"的表述可能误导设计者认为 3 次鉴定后没有惩罚/收益。

**严重程度**：低

**建议**：
1. 将表格中"u=0.18 (约基准)"改为"u=0.18 (接近基准)"，标注实际修正系数为约 x1.01/x0.98/x0.98 而非整数 x1.00。
2. 或将"真正的零点"设为 u=0.175 (normalize=0.50)，使所有修正系数在此点精确为 x1.00。这需要将 normalize 范围微调为 [0.05, 0.30] -> 中点 0.175。

### 5. AP 投资回报率分析：鉴定 vs 洞察的经济价值不对称

**问题**：鉴定系统有三方向精度收益（A/D/C'）作为"纯收窄"的经济回报，但洞察系统的 1 AP 投资缺乏等价的经济量化。这可能导致 AP 分配决策偏向鉴定。

**分析**：

鉴定 1 AP 的可量化收益（以 $3000 物品为例）：
- 方向 A：开价修正从 x1.08 到约 x1.03（2 次后），节省约 $150 起始距离
- 方向 D：让步乘数从 x0.70 到约 x0.89（2 次后），每轮多获约 $60 让步
- 方向 C'：出售波动范围从 [-30%,+10%] 收窄到约 [-12%,+6%]，期望值提升约 $210

合计约 $420/AP（粗略估算，假设 2 AP 投入后与 0 AP 的差距 $840 平摊）。

洞察 1 AP 的收益：
- 得知心理倾向（定性信息）
- 底线暗示（模糊范围）
- 道德信息（叙事）
- **无直接经济修正**

如果玩家纯粹追求经济最优，鉴定永远优于洞察。洞察的价值完全在"叙事/情感"维度，但精度收益机制加强了鉴定的经济维度，进一步拉大了两者的"硬"价值差距。

**严重程度**：中

**建议**：
1. 考虑给洞察增加一个经济性收益，例如：使用洞察后，如果 NPC 是"虚张声势"类型，让步概率 +10%（直接降低议价成本）。
2. 或在设计文档中明确承认这种不对称是有意的：鉴定=经济工具，洞察=叙事工具。AP 竞争的核心不是"哪个赚更多"，而是"你想要钱还是想要故事"。
3. 如果选择方案 2，建议在策略深度表（3.8 节）中增加"洞察 vs 鉴定"的决策分析，帮助玩家理解两者的不同价值维度。

### 6. 方向 C' 黑市波动的期望偏移在极端场景下可能过于惩罚

**问题**：方向 C' 设计中，uncertainty=0.30 时出售波动范围为 [-30%, +10%]，期望偏移为 -10%。这个惩罚在高价值物品上会造成巨大的绝对金额损失。

**分析**：

以 realValue = $10,000 的古董为例：
- 鉴定充分 (u=0.05)：波动 [-2%, +2%]，期望偏移 0%，日基准价 x $10,000
- 盲收 (u=0.30)：波动 [-30%, +10%]，期望偏移 -10%，期望售价 $9,000

期望损失 = $1,000。对比玩家初始资金 $10,000 和每周医药费 $1,000，一件高价物品的盲收波动就可能吞掉一周的医药费。

再叠加方向 A（开价高 8%）和方向 D（让步慢 30%），盲收高价物品的综合惩罚可能达到物品价值的 15-20%。对于 $10,000 物品，这是 $1,500-$2,000 的差距。

**但**这可能正是设计意图——高价值物品"盲收"应该是高风险行为。问题在于：当每日只有 1-4 位客户（经济参数显示 max_customers_per_day=4，实际配置也为 4），如果高价物品出现在 AP 耗尽之后，玩家要么放弃利润丰厚的交易，要么被迫盲收承受巨大惩罚。这可能不是"有意义的选择"而是"被迫接受惩罚"。

**严重程度**：中

**建议**：
1. 在文档中明确标注 C' 惩罚的绝对金额范围，针对不同价值档位给出示例（低价 $500、中价 $3000、高价 $10000），让设计者看到极端场景的影响。
2. 考虑对 C' 波动设置绝对值上限（例如最大波动不超过 $2000），防止高价物品的惩罚过于极端。
3. 或将 C' 的非对称分布斜率略微收敛（例如从 [-30%,+10%] 改为 [-25%,+10%]，期望偏移 -7.5%），保留惩罚但降低极端风险。

### 7. 格物系统与白天鉴定的 uncertainty 衰减率不一致可能产生套利

**问题**：格物系统文档 (4.1 节) 指出夜间格物的估价收窄率为 ~20%/次，而白天鉴定为 ~15%/次。但 uncertainty 的衰减系数（x0.85）似乎只对白天鉴定有定义。

**分析**：

鉴定系统文档定义：每次鉴定 uncertainty x0.85（约 15% 收窄）。格物系统文档说"收窄 ~20%"。如果格物的 uncertainty 衰减是 x0.80（20% 收窄），那么格物比白天鉴定更高效。

但更重要的是：**格物每晚只需 1 精力（非 AP），且精力与 AP 是独立资源池**。如果格物的 uncertainty 收窄效率高于白天鉴定，玩家可能形成策略：白天完全不鉴定（省 AP 给洞察或其他用途），依赖夜间格物来降低 uncertainty，然后第二天客户来赎回前卖出库存。

但这只对**库存中的物品**有效，对当天议价中的物品无效（议价在白天完成，格物在夜间）。所以套利空间有限。

不过，精度收益机制 A/D 都是"进入议价阶段时一次性计算"，如果物品是续当/赎回场景，NPC 第二天回来时 uncertainty 已被格物压低，A/D 收益会提升。这是否是设计意图？

**严重程度**：低

**建议**：
1. 在鉴定系统文档中明确格物的 uncertainty 衰减系数（是 x0.80 还是其他值），与格物系统文档对齐。
2. 明确精度收益机制在续当/赎回场景中的行为：如果 NPC 回来续当，uncertainty 是读取当前值（包含格物改善）还是锁定为原始成交时的值？
3. 当前设计中 A1 "进入议价阶段时一次性计算"的规则需要澄清：续当时是否重新计算？

### 8. 鉴定失误事件的触发条件创造了反直觉的"安全区"

**问题**：鉴定失误 (MISHAP) 仅在 uncertainty < 0.15 时触发。这意味着只有在鉴定已经比较充分（约 5+ 次鉴定后）时才会遭遇失误。越努力鉴定，越可能遭遇挫折。

**分析**：

从数值角度看：
- 鉴定 0-4 次：uncertainty >= 0.157，MISHAP 不触发，事实上"安全"
- 鉴定 5+ 次：uncertainty < 0.15，MISHAP 有 5% 概率触发
- MISHAP 效果：uncertainty += 0.05，相当于"回退"约 1-2 次鉴定

从玩家感知看：你已经花了 5 AP 深入鉴定，突然"看错了"导致精度回退——这在心理上很挫败。而且在实际游戏中，鉴定 5 次消耗了半天的 AP（10 AP/天），这时触发失误的惩罚感尤其强烈。

从策略角度看：这创造了一个"3-4 次鉴定是甜蜜点"的隐性规则——足够降低 uncertainty 获得精度收益，又不会触发 MISHAP。但这不一定是设计意图。

**严重程度**：低（MISHAP 概率只有 5%，且有"同一物品最多 1 次负面意外"的限制）

**建议**：
1. 如果设计意图是"防止过度鉴定"，则在文档中明确说明这一策略含义。
2. 如果设计意图只是增加随机性，考虑移除 uncertainty < 0.15 的条件限制，让 MISHAP 在任何阶段都有可能触发（但首次鉴定仍然豁免）。这样玩家不会有"安全区"心态。
3. 或改为：MISHAP 概率随 uncertainty 降低而增加（如 5% x (0.30 - uncertainty) / 0.25），在 u=0.30 时概率为 0%，u=0.05 时概率为 5%。这更符合"越深入越容易失误"的叙事逻辑。

### 9. 收购轨精度修正 (C' 收购) 与黑市系统的关系未明确

**问题**：方向 C' 定义了"收购精度修正"公式 `lerp(1.00, 0.85, normalize(uncertainty))`，但黑市系统是否已经存在、其基础收购系数如何定义，在鉴定文档和关联文档中都未充分说明。

**分析**：

C' 收购精度修正公式：
```
收购价 = realValue x 收购系数 x (1 + 升级加成) x (1 - 佣金) x 收购精度修正
```

这里的"收购系数"、"升级加成"、"佣金"都引用了尚未定义的黑市系统参数。如果这些参数未确定，收购精度修正的实际效果无法评估。

特别是：如果基础收购系数已经很低（比如 0.60），那么精度修正 0.85 x 0.60 = 0.51（盲收物品黑市只收 51% 真值），这惩罚是否合理取决于整体经济模型。

**严重程度**：低（黑市系统尚未实现，C' 本身标注为待实现）

**建议**：
1. 在文档中增加占位说明：收购精度修正的实际影响取决于黑市系统基础参数，需要在黑市系统设计完成后验证端到端数值。
2. 给出一个假设性示例：假设基础收购系数 = 0.70，标注精度修正后的实际收购价范围。

### 10. 特征发现概率公式的累积效果分析缺失

**问题**：文档中特征发现概率定义为每次鉴定独立判定（经济参数文档：`P = 0.5 - difficulty x 0.3`），但缺少累积多次鉴定后"至少发现一个特征"的概率分析。

**分析**：

以中等难度特征 (difficulty=0.5, P=35%) 为例：
- 鉴定 1 次后发现概率：35%
- 鉴定 2 次后至少发现的概率：1 - (0.65)^2 = 57.8%
- 鉴定 3 次后：1 - (0.65)^3 = 72.5%
- 鉴定 5 次后：1 - (0.65)^5 = 88.4%

以高难度特征 (difficulty=1.0, P=20%) 为例：
- 鉴定 1 次：20%
- 鉴定 3 次：48.8%
- 鉴定 5 次：67.2%
- 鉴定 7 次：79.0%

这意味着：
1. **FAKE 特征的 discoveryDifficulty=0.6**（代码中默认值），P=32%。鉴定 3 次后仍有 31.4% 概率未发现。对于假货这种核心风险特征，约 1/3 的玩家花了 3 AP 也发现不了，可能会感到沮丧。
2. 但 MISHAP 事件会跳过特征判定（代码中 `if (event.type !== 'MISHAP')` 跳过），所以在鉴定失误轮次中，特征发现概率为 0。

**严重程度**：中

**建议**：
1. 在设计文档中增加"累积发现概率表"，让设计者直观看到多次鉴定后的特征发现期望。
2. 考虑是否需要"保底机制"：例如连续鉴定 N 次未发现特征时，下次发现概率提升（类似手游的保底抽卡）。这可以缓解"反复鉴定却什么都没发现"的挫败感。
3. 对于 FAKE 类特征，考虑降低 discoveryDifficulty 或提供额外的发现渠道（例如格物也有概率发现 FAKE），因为未发现假货的后果非常严重。

### 11. 精度收益三方向的"总收益上限"需要压力测试

**问题**：文档 3.7 节列出了平衡约束"低 uncertainty 不能过强"，但缺少量化分析来验证三方向叠加后的极端场景。

**分析**：

以 $5000 物品、CALM NPC (耐心 4, 让步概率 25%, 让步幅度 10%) 为例：

**极致鉴定场景 (u=0.05)**：
- A1: 开价 x0.92 = $4600 (vs $5400 的 u=0.30，节省 $800 起始距离)
- A2: 侮辱线 x0.85，安全试探区扩大约 $525
- D: 让步 x1.30，每轮多获 $150
- C': 出售几乎无波动，期望偏移 0%

**完全不鉴定场景 (u=0.30)**：
- A1: 开价 x1.08 = $5400
- A2: 侮辱线 x1.10，试探空间缩小
- D: 让步 x0.70，每轮少获 $150
- C': 期望偏移 -10%，即期望损失 $500

假设 3 轮推拉成交，D 方向差距 = 3 x $150 x 2（双向，玩家和 NPC 都受影响）= $900。
A1 差距 = $800。
C' 期望差距 = $500。
**总收益差距 = 约 $2,200**，占物品价值 44%。

这个比例相当高。对比 AP 成本（约 5 AP 达到 u=0.05），每 AP 产生约 $440 的经济价值。每日 10 AP，如果全部用于鉴定高价物品，理论上可创造 $4,400 的额外价值。对比每日运营成本 $50 和每周医药费 $1,000，鉴定的 AP 回报率非常可观。

**严重程度**：低（高价物品本身就应该值得深入鉴定，且 5 AP 投入不低）

**建议**：
1. 在文档中增加"极端场景压力测试"表，分别计算 $500、$3000、$10000 物品在 u=0.05 和 u=0.30 时的总收益差距，确认设计者认可这些数值范围。
2. 特别关注：当物品价值 < $500 时，精度收益的绝对值（约 $220）可能不值得投入 5 AP（每 AP 仅 $44），这是否符合设计意图中"低价值物品不值得鉴定"的期望。

---

### 12. 灵光一闪的期望值对 uncertainty 路径的影响

**问题**：灵光一闪 (10% 概率, x0.60) 会显著改变 uncertainty 的预期衰减曲线，但文档只给出了"等效约多鉴定 1.5 次"的粗略估算。

**分析**：

考虑期望衰减（E[uncertainty after N appraisals]）：

不考虑灵光一闪：`0.30 x 0.85^N`
- N=3: 0.184
- N=5: 0.133

考虑灵光一闪（每次 10% 概率 x0.60, 90% 概率 x0.85）：
- 每次期望乘数 = 0.10 x 0.60 + 0.90 x 0.85 = 0.060 + 0.765 = 0.825
- N=3: 0.30 x 0.825^3 = 0.168
- N=5: 0.30 x 0.825^5 = 0.114

差异：3 次鉴定后，考虑灵光一闪的期望 uncertainty 为 0.168（vs 不考虑的 0.184），差约 0.016。对应 normalize 值差约 0.064，对修正系数的影响约 1%。

这确认了灵光一闪的**期望**影响较小（符合设计意图），但**方差**显著：如果 3 次中触发 1 次灵光一闪，uncertainty = 0.30 x 0.85 x 0.60 x 0.85 = 0.130，直接进入"中等偏优"区间。如果 3 次都没触发，uncertainty = 0.184（普通区间）。

这创造了一种"赌博感"：运气好的玩家用 3 AP 获得了 5 AP 的效果，运气差的玩家感觉灵光一闪"不存在"。

**严重程度**：低（这正是概率机制的设计目的——增加变数）

**建议**：
1. 在文档中增加期望衰减曲线对比表（考虑/不考虑灵光一闪），让设计者清楚实际的 uncertainty 分布。
2. 考虑是否需要"保底灵光一闪"：例如连续 5 次未触发时，第 6 次概率提升到 30%。这可以减少极端不幸运的情况。

## 亮点

- **连续函数替代三档离散分级**：这是前次评审的核心改进，效果显著。消除了"鉴定 3 次到 MEDIUM 零收益"的设计缺陷，每次 AP 投入都有可感知的增量回报。normalize 函数设计简洁优雅（Sylvester 优雅性启发第 2 条：能写在餐巾纸上）。

- **方向 C' 替代原方向 C**：黑市波动绑定 uncertainty 远优于原设计的"流当一次性偏差"。新设计在感知时机（持续 vs 延迟）、对比基准（同界面并列）、决策空间（等好价 vs 割肉）三个维度上都更优。非对称分布设计精巧，确保盲收在统计上是劣策略。

- **三方向的时间轴分布**：A（即时）、D（渐进）、C'（持续）形成了教科书式的"叠加强化循环"（Sylvester），消除了动机空白。玩家在鉴定后的每个阶段都能感受到投资回报。

- **灵光一闪与特征发现的优先级规则**：明确的交互规则（FAKE/JACKPOT 优先，非跳变特征正常叠加）避免了规则冲突，体现了文档的严谨性。

- **策略深度矩阵 (3.8 节)**：七个决策因素的"倾向鉴定/倾向跳过"对照表，清晰展示了多维度权衡空间。这不是"要不要鉴定"的简单二选一，而是一个涉及物品价值、客户类型、NPC 风格、AP 余量、客流量、当金水平、黑市计划的综合决策——这正是 Sylvester 所说的"决策信息平衡"。

---

## 总体评价

鉴定系统 v1.6 的数值设计在整体框架上是**严谨且自洽**的。连续函数模型解决了前版离散分级的核心缺陷，三方向联动形成了清晰的投资回报链条。从 Sylvester 的优雅性角度看，uncertainty 这单一参数同时驱动三个方向的修正系数，用最少的输入产生最多的系统交互——这是值得保留的设计美感。

主要风险集中在三个领域：**一是设计文档与代码/经济参数文档之间的同步问题**（发现 1、3），这些不一致可能在后续开发中导致理解偏差；**二是 AP 投资回报的不对称性**（发现 5），鉴定的经济收益远超洞察，可能扭曲 AP 分配决策；**三是边缘场景的极端惩罚**（发现 6），高价物品的盲收惩罚叠加后可能过于严厉。

建议优先处理发现 1（事件概率同步）、发现 3（经济参数文档更新）、发现 10（特征发现保底机制评估），这三项直接影响玩家体验的可预测性和公平感。其余发现为中低优先级的优化和文档完善工作。
