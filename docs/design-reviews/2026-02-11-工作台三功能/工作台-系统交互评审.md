## 系统交互矩阵

工作台系统 v2.0（三分法：修复/伪造/重铸）与以下系统存在数据流交互：

| 关联系统 | 交互方向 | 数据流 | 交互密度 |
|---------|---------|--------|---------|
| **格物与精魄系统** | 精魄流入 -> 工作台消耗 | 匠心/旧影/灵韵点数 | **高** |
| **声誉系统** | 工作台操作 -> 声誉变化 | 三轴声誉delta | **高** |
| **鉴定系统** | 白天信息 -> 夜间决策 | trait/uncertainty/估价 | **高** |
| **典当业务系统** | 物品状态 -> 操作许可 | ACTIVE/FORFEIT状态 | **高** |
| **洞察系统** | 客户信息 -> 重铸归还决策 | 客户性格/情感分量 | **中** |
| **黑市系统** | 伪造品 -> 出售渠道 | 价值系数/标签 | **中** |
| **物品标签系统** | Tag操作 -> 变体切换 | StateTag/EssenceTag | **高** |
| **店铺升级系统** | 工坊扩建 -> 精力上限 | 精力点数 | **低** |
| **NPC/客户系统** | 客户数据 -> 归还判定 | 性格/情感 | **中** |
| **经济系统** | 价值系数 -> 利润 | 价格计算 | **中** |

## 发现列表

### 1. 🔴 声誉映射错位：伪造路线与声誉三轴的对应关系不完整

**问题**：工作台文档将伪造(Forge)映射到"黑道"声誉轴，但声誉系统 v2.3 中第三轴已统一更名为"清白(Innocence)"，且声誉文档中没有任何关于工作台伪造操作的声誉条目。

**分析**：
- 声誉系统文档的行为影响矩阵中，完全没有涵盖工作台三路线的声誉变化。
- 工作台文档第 2 节表格写的是"声誉轴: 黑道"，但声誉系统 v2.3 已确认第三轴为"清白(Innocence)"，两份文档术语不一致。
- 修复归还的"人情+10, 商誉+1"、伪造违约的"人情-15, 商誉-10"、重铸归还四种结果的声誉数值，均未出现在声誉系统的行为影响矩阵中。
- 特别是伪造路线：设计意图是映射"黑道"，但伪造操作本身（夜间工作台操作）并不涉及赃物交易或黑市行为，它更像是"制造赝品"。在声誉系统中，"交易赝品（被发现）"对应商誉-3，而非清白轴。伪造操作本身应该影响哪个轴、影响多少，缺乏权威定义。

**建议**：
1. 工作台文档统一使用"清白(Innocence)"替代"黑道"，与声誉系统 v2.3 保持一致。
2. 在声誉系统文档的行为影响矩阵中增加"工作台操作"节点，明确定义三路线各操作的声誉变化。
3. 重新审视伪造与清白轴的映射逻辑：伪造赝品并出售更合理的映射是"商誉-X"（交易赝品）+ "清白-X"（欺诈行为），而非单纯映射到一个轴。

### 2. 🔴 精魄消耗与格物产出的数值匹配缺乏验证

**问题**：工作台配方消耗大量精魄（如宫廷御制需要匠心50+旧影60+灵韵30=140点），但格物系统的产出类型由物品的G2标签决定，玩家能否在合理时间内积累所需的三种精魄配比，缺乏跨系统数值验证。

**分析**：
- 格物产出按物品G2标签决定类型：GOLD/MECHANICAL -> 匠心, VINTAGE_REAL/SENTIMENTAL -> 旧影, ARTISTIC -> 灵韵。
- 每件物品每晚格物一次，产出15-25点（Lv1），知识池60-200。一件普通物品总产出约60-100点+顿悟暴击25%。
- 宫廷御制配方需要 匠心50 + 旧影60 + 灵韵30 = 140点，且这三种精魄来自**不同类别的物品**。
- 问题在于：如果玩家库存中恰好没有ARTISTIC标签的物品，灵韵就完全无法获取。玩家可能在3-5天内积累了足够的匠心和旧影，但灵韵永远凑不齐。
- 格物系统文档 6.1 节说明精魄是"中性资源"，由物品本身决定产出配比。但工作台配方隐式假设玩家能获取三种精魄的均衡供给，这取决于物品供给的随机性。

**建议**：
1. 在经济参数文档中增加"精魄产出-消耗平衡表"，按每日客户构成（1叙事+3填充）估算三种精魄的日均产出。
2. 确认填充客户的物品标签分布是否能保证三种精魄的基本供给。若某类精魄系统性稀缺，配方消耗需要相应调整。
3. 考虑在"共鸣"机制中加入跨类型精魄转换的可能性，作为稀缺精魄的应急来源。

### 3. 🔴 重铸归还的"物品情感分量"数据来源未定义

**问题**：重铸归还的四种结果依赖"物品情感分量"和"客户性格"两个因素，但"物品情感分量"的判定依据（STORY/SENTIMENTAL trait + 客户对话中的情感表达）在数据层面缺乏明确的获取路径和存储位置。

**分析**：
- 工作台文档 7.4 节定义了判定因素："有 STORY / SENTIMENTAL trait，或客户在典当时表达过情感依附"。
- **SENTIMENTAL trait**: 在代码中（`tags.ts`），SENTIMENTAL 是 G2 AttributeTag，定义为物品固有属性。这个信息可以通过白天鉴定发现，数据路径清晰。
- **STORY trait**: 设计文档中提到的 STORY 特征在鉴定系统的特征类型表（K节）中存在，但在代码的 `tags.ts` 中没有对应的 ItemTag 定义。STORY 特征如何在 Tag 系统中表示？它是 ItemTrait（鉴定发现的特征）还是 ItemTag（标签系统的标签）？
- **客户对话中的情感表达**: "客户在典当时表达过情感依附"这个信息在哪里存储？交易完成后客户对话数据是否被保留？在 NPC 生成数据中没有看到一个明确的"情感依附度"字段。
- **客户性格**: 工作台文档提到"实用型/NAIVE"、"情感型/有深厚故事背景"、"SAVVY/精明型"，但这些与洞察系统的 BehaviorTag 系统只有部分重叠。"实用型"在 BehaviorTag 中没有直接对应。

**建议**：
1. 明确"物品情感分量"的数据字段定义：建议在物品上增加一个计算属性 `emotionalWeight: 'HIGH' | 'LOW'`，由系统根据 trait（SENTIMENTAL/STORY）和 NPC 对话数据自动判定。
2. 明确"客户性格"与 BehaviorTag 的映射表：哪些 BehaviorTag 组合映射到"实用型"/"情感型"/"精明型"。
3. 定义 NPC 对话中"情感依附"信息的存储方式：是否在 PawnInfo 中增加 `emotionalAttachment: boolean` 字段？

### 4. 🟡 三选一互斥规则与 WorkState 类型不匹配

**问题**：工作台文档定义了修复/伪造/重铸三选一互斥，但代码中的 `WorkState` 类型仅有 `'DEFAULT' | 'RESTORED' | 'REFORGED'` 三个值，没有 `'FORGED'` 状态来表示伪造路线。

**分析**：
- 代码中 `RecipeType` 也只有 `'RESTORE' | 'REFORGE'` 两种，没有 `'FORGE'` 类型。
- 代码中所有伪造配方（如 `reforge_fake_history`）当前被归类为 `REFORGE` 类型，即伪造和重铸在代码层面是合并的。
- v2.0 设计文档将伪造独立为第三路线，但代码架构尚未反映这一变更。如果要实现三选一互斥，需要：
  - `WorkState` 增加 `'FORGED'` 值
  - `RecipeType` 增加 `'FORGE'` 类型
  - 配方数据结构需要区分 FORGE 和 REFORGE
  - 互斥检查逻辑需要从二分法升级为三分法

**建议**：
1. 这不是设计文档的问题，而是实现差距。建议在工作计划中标注为 P0 阻塞项：代码架构需要从二分法升级为三分法。
2. 设计文档中补充明确的状态转换规则：`DEFAULT -> RESTORED / FORGED / REFORGED`，其余转换全部非法。

### 5. 🟡 伪造品的出售渠道未显式定义

**问题**：伪造后的物品如何出售？通过正常客户出售还是通过黑市？两个渠道的规则是否有差异？

**分析**：
- 工作台文档 3B 节提到"出售给不识货的买家"和"冒充古董/稀有品出售"，但没有明确指出这些买家从哪里来。
- 黑市系统文档 7.1 节提到"假货: 可售（可能被压价）"，说明黑市接受假货但可能压价。
- 但伪造品的核心定位是"卖给不识货的人"。当前系统中的买家只有两类来源：(a) 客户赎回（不适用于伪造品）、(b) 黑市。黑市的联系人是"专业买家"，他们不太可能是"不识货的买家"。
- 设计文档提到的 x2.5~x4.0 价值系数，是基于物品真实价值还是伪造后的"表象价值"来计算最终售价？如果通过黑市出售，黑市的收购系数（1.1-1.4倍真实价值）和伪造的价值系数（x2.5-x4.0）如何叠加？

**建议**：
1. 明确伪造品的出售渠道和定价逻辑。建议方案：
   - 伪造品通过黑市"玩家出售"渠道出售，售价 = 物品原始真实价值 x 伪造系数 x 出售系数 x 佣金修正。
   - 或者，设计一个新的出售渠道（如"不识货的收藏家"偶尔来访），但这增加了系统复杂度。
2. 明确伪造系数的计算基准：是乘以原始 realValue 还是替换 realValue。
3. 与黑市系统文档双向同步这个定义。

### 7. 🟡 信息闭环的数据保留问题

**问题**：工作台文档强调"从白天到夜晚的信息闭环"（白天鉴定的 trait 信息影响夜间工作台决策），但未明确这些信息在夜间工作台界面中如何呈现。

**分析**：
- 白天鉴定发现的 trait（如 SENTIMENTAL, STORY）存储在物品的 `revealedTraits` 字段中，这个数据在夜间仍然可用。数据流是通的。
- 但问题在于：白天洞察获取的客户信息（如"客户在典当时表达过情感依附"）是否在夜间工作台界面可见？
- 洞察系统的数据存储在客户对象上，但当客户离开后（交易完成），客户数据是否仍与物品关联？当前 `PawnInfo` 只记录了 `customerId`，但客户的洞察结果（行为描写、道德信息）是否被保留？
- 重铸归还决策需要"物品情感分量+客户性格"信息。如果这些信息在交易完成后丢失，玩家在夜间做重铸决策时就没有足够的信息依据。

**建议**：
1. 在 `PawnInfo` 或物品对象上增加关键信息摘要字段，如 `customerEmotionalProfile`、`pawnDialogueHighlights` 等，在交易完成时自动提取并保留。
2. 夜间工作台界面中，选择物品时应展示"白天记录摘要"，包括已发现的 trait 和客户信息片段。
3. 这与工作台文档 7.4 节"商人直觉"提示框的设计一致，但需要明确数据来源。

### 8. 🟡 修复归还与典当业务系统的赎回流程交互

**问题**：修复后归还客户的"人情+10"是在什么时机触发的？与典当业务系统的赎回结算流程如何整合？

**分析**：
- 典当业务系统的赎回流程（2.F 节）定义了：客户赎回时展示物品状态（在库/已售/已变卖）。
- 修复后归还的额外声誉奖励（人情+10, 商誉+1）是在赎回结算时附加的，还是单独触发的？
- 如果物品被修复后客户正常赎回，赎回流程已有"同意赎回: 商誉+2"的声誉。修复归还的声誉是叠加（商誉+2+1=+3, 人情+10）还是替代？
- 重铸归还的四种结果也需要在赎回流程中触发，但典当业务系统的赎回流程目前没有"物品被加工过"的分支。
- 伪造违约的触发时机也需要明确：是在伪造操作时立即记录为"预违约"，还是在客户赎回时才触发违约？

**建议**：
1. 在典当业务系统的赎回结算流程中增加"物品加工状态检查"步骤，根据 WorkState 分支处理。
2. 明确声誉叠加规则：修复归还的人情+10 与正常赎回的商誉+2 应该是叠加关系（两者奖励不同的轴）。
3. 伪造违约应在客户赎回时触发（而非伪造操作时），因为只有当客户实际来赎回时才产生违约后果。如果物品在赎回前已死当，则不触发违约。

### 9. 🟡 工坊扩建升级与三路线的关系

**问题**：店铺升级系统中的"工坊扩建"升级只提供精力上限增加，但三条路线对精力的消耗不同（修复1-3精力，伪造3精力，重铸2-3精力）。升级是否应对三路线有差异化影响？

**分析**：
- 工坊扩建 Lv3 的"解锁新夜间活动类型"描述为"具体解锁内容根据夜间工作台系统的后续设计确定"。
- v2.0 的三功能设计可以自然承接这个解锁点：例如 Lv3 解锁伪造路线（作为"高级"功能），增加策略进度感。
- 但如果伪造从游戏初始就可用（工作台文档没有提到解锁条件），那么 Lv3 的质变解锁就需要另找定义。
- 工作台文档 5.1 节的配方结构有 `unlock_day` 字段，但没有提到是否需要升级前置。

**建议**：
1. 考虑将伪造路线与工坊扩建等级关联：例如 Lv1 只能修复，Lv2 解锁重铸，Lv3 解锁伪造。这样既填充了 Lv3 质变解锁的内容，又为三路线提供了解锁节奏。
2. 或者保持三路线初始全部可用，但 Lv3 解锁"高级配方"（如宫廷御制），这与当前 `unlock_day` 设计不冲突。
3. 无论哪种方案，都需要在两份文档中同步定义。

### 10. 🟢 三选一互斥与"格物底材独立"规则的一致性

**问题**：格物系统文档明确规定"格物与重铸底材关系互不影响"（设计决策记录），但在三选一互斥规则下，这个独立性是否仍然成立？

**分析**：
- 格物系统 v1.1 设计决策："物品的知识池消耗和重铸底材身份互不影响。知识池被完全榨干的物品，仍然可以作为重铸底材使用。"
- 在三选一规则下，这个规则不需要修改：格物是信息提取操作，不属于修复/伪造/重铸三路线之一。格物不改变物品状态（不影响 WorkState），因此与三选一互斥不冲突。
- 策略深度更好了：玩家可以先格物数天榨干知识池获取精魄，再用同一物品作为底材走三条路线之一。

**建议**：无需修改。但建议在工作台文档中补充一句说明："格物操作不属于三路线之一，格物后物品仍可选择任意路线。"

## 跨系统发现

### [跨系统: 声誉系统 <-> 工作台系统] 术语不一致
工作台文档使用"黑道"，声誉系统使用"清白(Innocence)"。需要统一。

### [跨系统: 鉴定系统 <-> 工作台系统] STORY trait 双重身份
鉴定系统将 STORY 定义为"特征类型"（ItemTrait），工作台系统将其用作"物品情感分量"判定依据。但 STORY 在标签系统（ItemTag）中不存在，它只是 Trait 分类中的一种类型。需要明确 STORY 在判定逻辑中的数据路径：是通过 `item.revealedTraits.filter(t => t.type === 'STORY').length > 0` 来判定，还是通过 ItemTag？

### [跨系统: 洞察系统 <-> 工作台系统] 客户信息生命周期
洞察系统获取的客户心理信息在交易完成后是否保留，直接影响工作台重铸归还决策的信息基础。两个系统需要就"客户信息持久化"达成一致。

### [跨系统: 黑市系统 <-> 工作台系统] 伪造品定价公式
黑市系统定义了假货"可售（可能被压价）"但未定义压价幅度。工作台系统定义了伪造系数（x2.5~x4.0）但未定义出售渠道。两个系统需要共同定义伪造品的最终定价公式。

### [跨系统: 代码实现 <-> 设计文档] 架构落差
代码仍使用二分法（RESTORE/REFORGE），设计文档已升级到三分法（RESTORE/FORGE/REFORGE）。`WorkState`、`RecipeType`、配方数据结构均需要升级。这是实现层面的 P0 阻塞项。

## 亮点

### 三路线道德映射的设计优雅性
将修复/伪造/重铸分别映射到手/眼/心三象征，并对应利他/诱惑/家长主义三种道德问题，这是一个非常优雅的设计。三路线在机制、叙事、美学三个层面同步强化了"三元道德"主题，符合 Schell 的统一透镜（Lens #9）要求。

### 信息闭环的设计意图
将白天鉴定/洞察的信息与夜间工作台决策连接，提升了信息采集行为的价值，这是一个出色的跨系统涌现性设计。它让鉴定系统的 AP 投资在更长的时间跨度上产生回报，符合 Sylvester 的"决策有延迟后果"原则。

### 重铸归还的"善意僭越"机制
"不确定性归还"是全系统中最独特的设计。它将一个罕见的道德问题（家长主义）转化为了可玩的机制，且结果的不确定性由可观察的信息（trait、客户性格）部分缓解，创造了"有依据的判断 vs 纯赌博"之间的技能弹性。这符合 Sylvester 对"深度"的定义。

### 凝视时刻的情感设计
操作后的 3-5 秒无交互凝视时刻，利用了 Sylvester 的"玩家只需感知可能性"原则。未发生的事件（归还还是出售？客户会怎么反应？）在这段静默中产生情感张力，这是一个巧妙的叙事节奏设计。

## 总体评价

工作台系统 v2.0 的三分法设计在理念层面非常出色，三路线与声誉三轴、道德三象征的对称映射体现了高度的设计优雅性。信息闭环（白天采集 -> 夜间决策）和"善意僭越"不确定性机制是独特且有深度的设计亮点。

然而，从系统间交互视角看，存在两个需要优先解决的问题：(1) 声誉映射的术语不一致和数值缺失，这是文档层面的阻塞问题，影响所有下游实现；(2) 重铸归还判定所依赖的数据（物品情感分量、客户性格）缺乏明确的获取路径和持久化方案，这是架构层面的设计缺口。此外，伪造品的出售渠道和定价公式需要与黑市系统协同定义，`TRENDING` 标签的存废需要确认，代码架构从二分法到三分法的升级需要纳入工作计划。

建议在正式实现前，优先解决声誉术语统一（发现 #1）、情感分量数据定义（发现 #3）、伪造品出售渠道（发现 #5）三项跨系统问题，确保系统间的契约明确后再进入实现阶段。
