# Teams 跨系统讨论综合报告：信息数据流

> **日期**: 2026-02-11
> **议题**: 白天信息采集（鉴定/洞察）与夜间工作台决策的数据流应如何打通？
> **涉及文档**: 重铸与修复系统 v2.0 + 洞察系统 v1.4 + 鉴定系统 v1.7
> **参与成员**: player-psychologist, systems-balancer, narrative-integrator

---

## 三方共识

### 共识 1: 双层模型——objectiveWeight（客观）+ perceptionTier（感知）分离

- **结论**: 信息数据流的核心架构是双层模型：
  - **objectiveWeight**（系统真实值）：基于物品trait + 客户属性计算，决定归还概率
  - **perceptionTier**（玩家感知层）：基于白天信息采集行为（鉴定次数 + 洞察使用），决定商人直觉文案的丰富度
- **关键决策**: **概率由 objectiveWeight 决定，不受 perceptionTier 影响**。信息投入创造"更知情的赌注"，不是"更好的赌注"。
- **三条论证**:
  1. 叙事自洽——客户性格不因你的无知而改变（narrative）
  2. 元认知激活——盲赌的自觉是有价值的心理体验（psychologist）
  3. 规则一致性——避免"系统在作弊"的感知（psychologist，Rouse原则）
- **信息价值的真正体现**: 完备信息让玩家能从多件物品中"选品"（挑选低情感物品重铸），而盲赌玩家无法做此优化。信息的价值在"选品决策"上，非单品概率上（psychologist）。

### 共识 2: 物品情感分量（emotionalWeight）采用三档离散化

- **结论**: emotionalWeight 映射为三档（低/中/高），不使用连续值或二元分类
- **计算输入**:
  - 物品trait STORY/SENTIMENTAL（已有鉴定数据）
  - 客户对话情感关键词（需新增提取）
  - 洞察第三层道德信息（需洞察系统输出）
  - 客户BehaviorTag中的SENTIMENTAL标记（已有数据）
- **三档的叙事维度差异**:
  - 低档：商人语气平淡，"应该没什么问题"
  - 中档：最高难度区——商人语气模糊，"说不准"
  - 高档：商人语气强烈，"这东西对他很重要"
- **双路线消费**: 同一个emotionalWeight被两条路线以不同叙事角度消费（narrative）：
  - **伪造**: "你能不能下得了手"——道德维度
  - **重铸**: "客户会不会接受"——预判维度

### 共识 3: 永远允许操作，不因信息缺失禁止工作台选项

- **结论**: 所有工作台操作始终可用，无论信息完备度
- **理由**:
  - 锁定选项把鉴定从"投资"变成"门票"——破坏决策弹性（balancer）
  - 禁止操作打破角色沉浸——商人面对未知物品也有选择权（narrative）
  - 信息缺失本身是不同的游戏体验，不是惩罚（psychologist）
- **替代机制**: blind档位增加叙事化确认弹窗——**摩擦不是墙**（balancer）
  - 弹窗内容不是系统警告，是商人的自我怀疑："你对这件东西和这个人都不了解。真的要凭感觉来？"（narrative）
  - 按钮文案叙事化：["凭直觉来"] / ["再想想"]（narrative）
- **绝对不做**: 灰化选项、显示信息完备度百分比、白天系统提示"你还没鉴定"

### 共识 4: perceptionTier 四档内部计算 + 三档叙事呈现

- **结论**: 系统内部使用四档感知层级，叙事层合并为三档呈现

| 内部层级 | 条件 | 叙事档位 | 商人直觉示例 | 凝视氛围 |
|----------|------|----------|-------------|----------|
| **blind** | 0次鉴定 + 无洞察 | 匮乏 | "你对这件东西和这个人一无所知" | 焦虑迟疑 |
| **glimpse** | 1+次鉴定 + 无洞察 | 部分 | "弦断了但木质不错...他放下时好像犹豫了。仅此而已。" | 不安 |
| **partial** | 有洞察 + 0-1次鉴定 | 部分 | "这东西有故事。他提到要付房租...但他是什么样的人？" | 谨慎 |
| **clear** | 2+次鉴定 + 有洞察 | 完备 | "他提到这是父亲留下的。手在发抖。这个人重感情——动它要三思。" | 从容 |

- **blind vs glimpse的关键区别**（narrative）: blind是"完全黑暗"，glimpse是"有一丝微光但不够照亮路"。后者更能激发下次主动采集信息的动机——"差一点就够了"。

### 共识 5: 信息以物品为入口持久化，叙事化呈现

- **结论**: 客户信息在交易结算时（RESOLVE_TRANSACTION/ADD_ITEM）一次性快照，附着到物品上
- **设计铁律**（narrative）: "持久化数据可以丰富，呈现给玩家的永远是一句话"
- **核心原则**（psychologist）: "替代记忆负担，不增加信息量"（Miller's Law 7±2）
- **叙事化呈现**: 工作台是"商人的独处时刻"，不是操作界面。所有数据通过商人回忆独白、凝视时刻氛围传递，不是数据面板。
- **洞察系统原则延伸**: "信息领域决定表达形式"——"人"的信息用行为回忆，"物"的信息用特征描述，"关系"的信息用对话回放（narrative）

### 共识 6: 归还结果文案承担"情感冲击 + 归因教学"双重功能

- **结论**: 四种归还结果（叹服/认可/不安/愤怒）文案必须包含归因线索
- **示例**:
  - 愤怒："他翻到背面——'爸爸，生日快乐。'——刻字不见了。你还记得他提到这块表是父亲留下的吗？"
  - 叹服："她当时好像只是说'帮我当个好价钱就行'——她对这把吉他并没有特别的执念。"
- **学习循环**: 3-5次归还体验后，玩家建立"情感分量→归还结果"的直觉映射，无需理解计算公式
- **自强化闭环**（psychologist）: emotionalWeight → 持久化 → 缺失处理 → 商人直觉 → 决策 → 归还结果 → 学习信号 → 下次白天行为改变

### 共识 7: 信息分层收集——基础免费 + 深层需AP

- **结论**: 白天信息采集分为两层：
  - **基础层**（免费自动）: 客户表面态度、对话关键词、BehaviorTag → 自动捕获
  - **深层**（AP投入）: 鉴定揭示trait、洞察揭示性格/道德信息 → 需要主动投资
- **理由**: 免费层防止完全盲猜（保底体验），AP层维持洞察的夜间投资价值
- **权重应反映信息获取成本**（psychologist）: 花AP获取的信息权重应高于免费信息，否则AP投入感觉"不值得"

### 共识 8: 第一次工作台体验——间接引导修复，不锁定路线

- **结论**: 通过场景设计让修复成为"最自然的选择"，但保留玩家自由选择权
- **引导手段**: 物品特征（适合修复）+ 精魄条件（不够重铸/伪造）+ 商人独白暗示 + 其他路线代价偏高
- **三阶段隐形训练**:
  1. **解锁前暗示**: 白天鉴定时偶尔商人独白——"这东西如果能……"
  2. **首次引导**: 工作台解锁时商人独白叙事化教学——"这块表…白天我仔细看过，齿轮断了三根。知道毛病在哪，修起来就有底。如果当时没细看…只能碰运气了。"（narrative）
  3. **渐退脚手架**: 3-5次后独白从明确指导变为模糊暗示，最终消失

### 共识 9: 降级只影响重铸归还——三路线信息依赖不对称

- **结论**: 修复和伪造不依赖客户信息（修复看物品状态，伪造不涉及归还），降级只影响重铸归还路线
- **天然策略定位**: "重铸归还 = 最需要信息投资的路线"——与工作台设计初衷一致（balancer）
- **降级矩阵**:

| 信息等级 | 修复 | 伪造 | 重铸出售 | 重铸归还 |
|---------|------|------|---------|---------|
| 完整（鉴定+洞察） | 正常 | 正常 | 正常 | 四格矩阵全功能 |
| 部分（仅鉴定） | 正常 | 正常 | 正常 | 性格缺失→偏中间结果 |
| 盲操作（均无） | 可操作 | 可操作 | 可操作 | 概率随机化+"一无所知" |

## 分歧与权衡

### 分歧 1: 持久化结构——独立 CustomerMemory vs 物品附加

- **systems-balancer**: 独立 `CustomerMemory` 存储在 `GameState.customerMemories`
  ```typescript
  interface CustomerMemory {
    customerId: string;
    customerName: string;
    behaviorTags: BehaviorTag[];
    primaryDisposition: Disposition;
    insightPerformed: boolean;
    insightLayer?: InsightLayer;
    pawnReason: string;
    emotionalKeyPhrase?: string;
    itemIds: string[];
    transactionDay: number;
    chainId?: string;
  }
  ```
  理由：同一客户可典当多件物品，避免冗余；天然支撑客户图鉴系统
- **player-psychologist**: 6字段直接附加到物品（emotionalWeight / customerBehaviorSnapshot / surfaceImpression / insightResult / moralContext / dialogueKeyFragment）
- **narrative-integrator**: 初始建议附加到 PawnedItem，但在交叉讨论后**改为接受 balancer 的独立存储方案**
- **最终趋向**: 三方趋向 balancer 方案（独立存储），但叙事呈现约束不变——无论底层如何存储，玩家看到的永远是叙事化的商人回忆
- **建议**: 采用 balancer 的 `CustomerMemory` 独立存储 + PawnedItem 上轻量 `workshopContext` 缓存（含 emotionalWeight、customerId、insightUsed、appraisalCount），工作台直接消费缓存，完整数据从 CustomerMemory 回退

### 分歧 2: objectiveWeight 计算——加权公式的具体权重

- **systems-balancer**: sentimentalValue(0.4) + SENTIMENTAL_trait(0.3) + STORY_trait(0.2) + emotionalAttachment(0.1)
- **narrative-integrator**: 建议调整为 sentimentalValue(0.3) + SENTIMENTAL_trait(0.25) + STORY_trait(0.3) + emotionalAttachment(0.15)
  - 理由：权重应偏向玩家能感知和采集的信息源。sentimentalValue是后台数值，不可感知；STORY trait是鉴定能发现的最直接信号
- **player-psychologist**: 建议积分制（trait:3 + 洞察:3 + 对话:2 + BehaviorTag:1），总分0-9映射三档
- **核心分歧**: balancer重视数值精度和经济模型，narrative重视感知因果链，psychologist重视简洁可实现
- **建议**: 初版用 **psychologist 积分制**（快速可实现），叙事层用三档呈现；迭代后可升级为 balancer/narrative 的加权公式。积分制是加权公式的退化形式，升级不改变接口。

### 分歧 3: DESPERATE 客户的归还反应映射

- **问题**: DESPERATE应映射为"开放型"（经济绝望→感激改良）还是"情感型"（最后救命稻草→不容改动）？
- **balancer建议**: 由 emotionalWeight 裁决而非标签裁决。低情感+DESPERATE=开放（"变好了更容易赎"）；高情感+DESPERATE=情感（"这是我唯一的东西"）
- **建议**: 采用 balancer 方案——保持两个维度（物品情感 × 客户性格）正交，避免对单一标签过度语义化

### 分歧 4: emotionalAttachment 数据来源

- **balancer选项A**（推荐）: 叙事设计师在story/模板中手工设定 `emotionalAttachment: boolean`
- **balancer选项B**: 通过 pawnReason 关键词自动判定
- **建议**: A为主（叙事客户由设计师标记），B为填充客户fallback（通过BehaviorTag推断）

## 融合方案

### 方案 1: PawnCustomerSnapshot——信息闭环的枢纽数据结构（balancer）

**核心**: 在成交时从 Customer 对象提取 7+1 个字段快照到 Item，打通完整数据通路。

```typescript
interface PawnCustomerSnapshot {
  customerId: string;            // 查找事件链
  customerName: string;          // 商人直觉文案
  behaviorTags: BehaviorTag[];   // 归还概率计算
  pawnReason?: string;           // 道德提示文案
  emotionalWeight: number;       // 归还结果矩阵因素1
  insightDepth: 0 | 1 | 2 | 3;  // 白天洞察层数
  isNarrative: boolean;          // 叙事 vs 填充客户
  emotionalAttachment?: boolean; // 设计师标记（叙事客户）
}
```

**生命周期**:
1. 创建：ADD_ITEM action 中从 Customer 对象提取
2. 消费：夜间工作台（归还弹窗、商人直觉、概率计算）
3. 存储：`Item.customerSnapshot`
4. 精简：物品 SOLD/REDEEMED 后降级为图鉴摘要

### 方案 2: 工作台数据消费契约表（balancer）

| 数据 | 来源系统 | 必需性 | 用途 | Fallback |
|------|---------|--------|------|---------|
| `tags: ItemTag[]` | 鉴定系统 | **必需** | 修复目标、重铸前置 | 无标签则修复不可用 |
| `baseValue` | 物品模板 | **必需** | 伪造/重铸价值计算 | 无fallback |
| `customerSnapshot.behaviorTags` | 典当快照 | **增强** | 归还概率计算 | 缺失→偏中间结果 |
| `customerSnapshot.emotionalWeight` | 典当快照 | **增强** | 归还概率计算 | 缺失→概率随机化 |
| `customerSnapshot.insightDepth` | 典当快照 | **增强** | 商人直觉语调 | 缺失→"一无所知" |
| `customerSnapshot.pawnReason` | 典当快照 | **增强** | 道德提示 | 缺失→不显示 |
| `revealedTraits` | 鉴定系统 | **增强** | 归还弹窗信息 | 无→信息更少 |

### 方案 3: "商人笔记"统一叙事载体（psychologist）

白天→夜间信息传递的统一叙事设备：
- **白天**: 系统检测到工作台相关信息事件时，商人内心独白自动"标记"——"这个人对这东西很在意...如果我要动它，得想清楚。"
- **夜间**: 每件物品旁显示已积累的商人笔记。笔记数量/深度与白天AP投入成正比
- **操作弹窗**: 重铸/伪造的风险提示中引用笔记。信息越丰富→直觉越具体；信息匮乏→"我说不好"

一次性解决三话题：emotionalWeight通过笔记密度间接传达 + 持久化的叙事呈现 + 信息完备度自然可视化。

### 方案 4: "雾中选择"分层呈现模型（narrative）

| 充实度 | 商人独白风格 | 重铸归还预判 |
|--------|-------------|-------------|
| **完整** | 确定："她很在意这东西，修好还给她是对的" | 明确倾向 |
| **充分** | 有把握但留余地："看起来她不太在意...但我也说不太准" | 模糊倾向 |
| **最低** | 不确定："我只知道这东西有什么毛病，但不了解她这个人" | 无倾向，仅机制说明 |
| **空白** | 警告性："我对这东西一无所知。盲修可能白费功夫" | 无倾向 + 确认弹窗 |

### 方案 5: 自强化信息闭环（psychologist）

```
白天：鉴定/洞察/对话 → 信息自动存入商人笔记
  ↓
夜间：工作台查看笔记 → 三选一决策
  ↓
归还结果：文案暗含归因线索（为什么成功/失败）
  ↓
次日复盘：夜间日记叙事化总结（"也许下次该多看一眼来人的表情"）
  ↓
下一个白天：玩家行为改变（主动鉴定/洞察更多）
  ↓
回到起点，信息更丰富、决策更有依据
```

三个强化循环叠加：鉴定循环（trait→精度收益）、洞察循环（情感信息→工作台判断）、工作台循环（操作→凝视→归还→学习），确保"one more turn"效应贯穿昼夜。
