## 发现列表

### 1 ⭐ 沉默变体与内心OS的双层叙事结构

**问题**: 无（亮点）。

**分析**: 代码实现展示了一个精心设计的叙事序列：NPC 台词（含20%概率的沉默变体）完成后，延迟800ms 显示商人内心独白。这构成了一个微观兴趣曲线：NPC的外部反应是"钩子"，短暂停顿制造悬念，商人内心OS是"内化高潮"。

从 Schell 的分形兴趣曲线理论看，这个环节自身就是一个完整的迷你曲线（入场 → 钩子 → 上升 → 高潮 → 收尾），嵌套在更大的"议价 → 送客 → 夜间"曲线中。

更重要的是，`DEPARTURE_THOUGHTS` 中的文案质量很高。例如 RESENTFUL 下的"那种眼神... 我以前见过"和 DESPERATE 下的"刚才那一瞬间，我看到了自己"——这些短句做到了"展示而非讲述"，通过暗示让玩家自行脑补更深层的含义。

### 2 🔴 送客环节零操作层 — 玩家能动感不足

**问题**: 送客阶段的全部交互仅为一个按钮："送客 (DISMISS)"。玩家在这个环节完全是被动接收者。

**分析**: Rouse 反复强调"玩家想要做，而不是看"。当前送客设计的核心矛盾在于：它追求"强制留白"的情感效果，但实现方式是剥夺玩家的所有能动性。

从 Sylvester 的优雅性启发来看（启发3："可多用途使用的机制"），这个环节引入了一个新阶段却只有一个行动动词——这意味着状态机增加了一个节点的成本，却只产出了"看文字"这一种体验。

议价系统有丰富的动词（选合同、调价格、坚持、让步、使用杠杆），送客阶段却只有"送客"。从玩家体验来看，这是从"高操作密度"到"零操作密度"的断崖式下降。

前次评审（建议6/玩家能动感评分 3/5）已指出这个问题但未给出具体方案。

**建议**: 考虑在送客阶段增加 1-2 个可选操作，使其从"被动观看"变为"主动选择"。候选方案（不必全部采用，挑选1个最符合主题的即可）：

**方案A: "最后一句话"选择** — 玩家可以从2-3个选项中选择商人对离场NPC说的最后一句话。这不改变交易结果，但影响声誉微调和NPC后续态度。这把内心OS从"被动展示"变为"主动表达"。

**方案B: "赠予/挽留"按钮** — 在特定条件下（如NPC极度绝望），送客阶段出现一个额外按钮："等一下..."。玩家可选择给NPC一小笔额外的钱或资源，付出额外代价但获得人情声誉。这增加了"做好人的最后机会"的决策深度。

**方案C: 保持现状但缩短** — 如果坚持"留白"设计，则应确保这个"被动"环节极短（控制在3-5秒内自然过渡），避免"等待按钮出现"的烦躁感。

### 3 🟡 重复疲劳风险 — 每位客户都经历相同节奏的送客

**问题**: 文档描述"每次交易后都进入送客阶段"，但未讨论重复疲劳的防范策略。

**分析**: Schell 的兴趣曲线理论指出，休息点（Rest Points）的价值在于它们短暂且稀缺。如果每位客户都触发完全相同节奏的送客流程（看台词 → 等800ms → 看内心OS → 点按钮），这个"情感留白"会迅速退化为"机械仪式"。

从 Sylvester 的动机理论看，固定比例的强化模式（每次交易 = 一次送客）会导致"动机低谷"——玩家在第3-4次之后就会产生"赶快跳过"的冲动，此时"强制静默"反而变成恼人的阻碍。

实现代码中 `DEPARTURE_THOUGHTS` 每个情绪只有4条文案，假设每天2位客户、游戏持续30天，60次送客将产生大量重复。

**建议**:
1. **动态跳过机制**: 对于 NEUTRAL 满意度的普通交易（公事公办、无特殊情节），可以将送客简化为一个快速过渡动画（1秒淡出），不强制显示台词和内心OS。只有在情感强度高的场景（GRATEFUL/RESENTFUL/DESPERATE）或事件链关键节点时，才展开完整送客流程。
2. **文案池扩容**: 每个情绪等级至少需要 8-12 条台词变体和 6-8 条内心OS变体，以支撑30天游戏流程。当前各4条远远不够。
3. **渐进式丰富**: 随游戏进程推移，内心OS的内容应该发生变化——早期可以是初入行的生涩，中期是麻木与挣扎，后期是哲学性反思。这种"成长弧线"可以防止文案疲劳。

### 4 🟡 满意度模型粒度不足 — 四档情绪无法覆盖复杂场景

**问题**: `satisfactionLevel` 只有 GRATEFUL / NEUTRAL / RESENTFUL / DESPERATE 四个档位，但实际交易场景的情绪远比这丰富。

**分析**: 设计文档中"系统三"定义的判定逻辑过于简单：

- `Rate == 0 OR Offer > Valuation * 1.2` → Grateful
- `Rate == 0.2 OR Offer < MinPrincipal` → Resentful
- `Rejected` → Desperate

这忽略了几个重要场景：
- **NPC耐心耗尽主动离开**: 这是NPC的决定，不是玩家拒收，但当前可能归入"Desperate"（其实更接近NPC的愤怒/失望而非绝望）。
- **赎回/续当场景**: 客户来赎回物品是完全不同的情感基调（可能是"终于凑够钱了"的释然或"还是续当"的无奈），但文档未提及赎回场景的满意度逻辑。
- **高利贷但NPC感激**: 如果NPC极度缺钱，即使是20%利率，NPC也可能感激（"至少有人愿意收"），当前设计一刀切地将20%标记为Resentful。

**建议**:
1. 增加 1-2 个中间档位，如 "RELIEVED"（如释重负，适用于客户虽被压价但至少拿到了急需的钱）和 "BITTER"（苦涩，介于Neutral和Resentful之间）。
2. 满意度判定应综合考虑 NPC 的 urgency（紧迫度）和交易条件：高urgency + 20%利率可能是 RELIEVED 而非 RESENTFUL。
3. 赎回/续当场景需要独立的满意度判定逻辑和退场台词集。

### 5 🟡 送客与夜间独白的情感重复风险

**问题**: 文档提到送客OS"与昼夜系统的'睡前独白'机制联动"，但未定义如何避免两者传达相同信息。

**分析**: 代码中 `innerVoiceRegistry.ts` 同时包含 `DEPARTURE_THOUGHTS` 和 `BEDTIME_THOUGHTS`，两者的内容存在明显重叠：

- 送客: "别怪我... 我也要吃饭。"（RESENTFUL）
- 睡前: "我今天看见了那个人离开时的眼神... 我是不是做得太绝了？"（lastSatisfaction === RESENTFUL）

当天如果发生了一笔压价交易，玩家会在送客时听到一次道德感慨，然后在睡前再听到一次内容相似的道德感慨。这不是"联动"，而是"重复"。

从 Schell 的兴趣曲线角度看，两个情感峰值的内容高度相似会让第二个峰值（睡前独白）失去力量——玩家已经消化过一次同类情绪了。

**建议**:
1. **送客OS = 即时情绪反应（短、直觉性）**: "他恨我。但我活下来了。"
2. **睡前独白 = 延迟反思（长、理性/纠结）**: "今天那个人的事...我一直在想。如果当时多给他100块，结果会不同吗？但那100块可能就是妈妈的药钱。这笔账，怎么算都不对。"
3. 两者应在内容层面有明确的"情绪演变"关系——送客是"冲击"，睡前是"消化"，而非重复表达同一层面的感受。文档应明确这一设计约束。

### 6 🟢 缺少"NPC离场"的视觉表现规格

**问题**: 设计文档描述了"老兵的身影淡出"和"沉重的脚步声和关门声"，但没有定义不同满意度对应的视觉差异规格。

**分析**: 代码实现（`DepartureView`）已经通过 `borderStyle` 区分了不同满意度的头像边框颜色（GRATEFUL=琥珀色+辉光, RESENTFUL=暗红, DESPERATE=灰色+半透明），但文档中完全没有提及这些视觉规格。这意味着视觉差异化完全由程序员自行决定，缺乏设计指导。

从 Schell 的"美学"维度（元素四象限）看，送客环节的视觉表现直接影响情感传达效果，不应留给实现阶段随意发挥。

**建议**: 在文档"系统四: UI布局与交互"中补充各满意度的视觉规格表：

| 满意度 | 头像表现 | 背景氛围 | 过渡动画 | 音效 |
|--------|---------|---------|---------|------|
| GRATEFUL | 暖色辉光 | 柔和暖光 | 缓慢淡出 | 轻柔脚步+铃声 |
| NEUTRAL | 标准边框 | 中性 | 标准淡出 | 普通脚步+门声 |
| RESENTFUL | 暗红边框 | 阴冷 | 快速消失 | 重脚步+摔门声 |
| DESPERATE | 灰色+低透明度 | 暗沉 | 极慢淡出 | 拖沓脚步+叹息 |

### 7 ⭐ 无交易反馈面板 — 失败的具象化

**问题**: 无（亮点）。

**分析**: v1.2 新增的"无交易反馈面板"（红色边框 + XCircle 图标 + "交易未达成"）是一个值得肯定的设计。它解决了前次评审中指出的"什么都没发生"的空洞感。

代码实现还根据满意度细分了描述文案（"顾客不满意你的报价，愤然离去" vs "你拒绝了这笔交易" vs "双方未能达成一致"），提供了差异化反馈。

从 Rouse 的"信息反馈"原则看，让失败也有明确的视觉和文字回响，避免了"只有成功才有反馈"的偏差。这使得"拒收"本身也成为了一个有重量的决策。

### 8 🔴 送客环节在兴趣曲线中的定位缺乏设计 — 从高潮到低谷的落差过大

**问题**: 议价环节是典型的"上升-高潮"（推拉博弈 → 成交/破裂），送客是"下降-休息"，但两者之间没有缓冲过渡。

**分析**: 用 Schell 的兴趣曲线透镜(#69)分析：

```
Interest
    |
    |      [议价高潮]
    |        /\
    |       /  \
    |      /    \  ← 断崖下降
    |     /      \
    |    /        \_______ [送客: 被动阅读]
    |   /                         \
    |  /                           \___[下一客户/夜间]
    |_/________________________________ Time
```

从推拉博弈的紧张高潮到送客的"强制静默"，玩家经历的是一个急剧的兴趣下降。没有"结算动画"（盖章、金币飞入）到"情感沉淀"的渐进过渡。

文档第2节的预期效果写道："盖上血红色的章 → 金币飞入账户 → 进入送客"，但这个"结算动画"的规格没有在送客文档中定义，也没有在其他文档中找到详细描述。如果结算动画过短或不存在，玩家会感觉从"激烈谈判"瞬间切换到"看一段文字"，体验割裂。

**建议**:
1. 在文档中明确定义"议价 → 结算 → 送客"的三阶段过渡时序：
   - 议价结束 → **结算动画 (1-2秒)**: 盖章、金币/物品动画，提供"尘埃落定"的仪式感
   - 结算动画结束 → **场景转换 (0.5-1秒)**: 商业元素淡出，灯光变暗，聚焦人物
   - 场景就绪 → **台词展开**: 打字机效果的退场台词
2. 每个阶段都需要有可感知的视听反馈（不是简单的界面切换），让玩家的情绪从"战斗结束的释放"自然过渡到"面对后果的沉重"。

### 9 🟡 赎回/续当/违约场景的送客缺乏设计

**问题**: 文档几乎完全围绕"典当"场景设计送客体验，但游戏存在赎回、续当、物品过期违约等多种场景，这些场景的送客流程未被覆盖。

**分析**: 从代码中可以看到 `SettlementCustomerView.tsx` 已经存在专门的赎回界面，且注释中明确写道 "Emotional changes are shown only in departure view"。这说明赎回场景确实会进入送客阶段，但设计文档没有定义：
- 赎回成功时的满意度是什么？（应该是 GRATEFUL 或 NEUTRAL？）
- 续当被拒时的满意度是什么？
- 物品过期违约（POST_FORFEIT 模式）时NPC来取回物品失败的情感反应？

这些场景的情感基调与典当场景完全不同，需要独立的退场台词和满意度判定逻辑。

**建议**: 在文档中补充以下场景矩阵：

| 场景 | 满意度来源 | 典型退场台词方向 |
|------|-----------|----------------|
| 赎回成功 | NPC赎回代价vs心理预期 | 释然 / 轻松 / 心疼（利息太高） |
| 续当成功 | 延期后的不确定感 | 无奈 / 焦虑 |
| 续当被拒 | 被迫违约 | 绝望 / 愤怒 |
| 违约后NPC来访 | NPC失去物品的情感 | 痛苦 / 认命 / 威胁 |

### 10 🟢 内心OS的触发概率缺乏规格定义

**问题**: 文档说商人内心OS"可设置概率触发，避免每次都出现"，但未给出具体概率值或触发条件。

**分析**: 代码实现中，内心OS实际上是**每次都出现**（`onCustomerTextComplete` 总是在800ms后设置 `showInnerVoice = true`）。这与文档的"概率触发"描述不符。

从防疲劳角度看，当前的"每次都出现"可能在短期内是合理的（玩家初期对每笔交易都有新鲜感），但长期会导致"又来了"的麻木感。

**建议**: 定义一个随游戏进程变化的触发策略：
- Day 1-7（新手期）: 100% 触发，帮助建立角色人格
- Day 8-14（适应期）: 60% 触发，NEUTRAL 交易降至 30%
- Day 15+（老手期）: 仅在高情感冲击场景（GRATEFUL/DESPERATE）或事件链关键节点时触发

### 11 🟢 "强制静默"的时长未定义

**问题**: 文档核心概念是"1-2秒的强制静默"，但没有明确这个静默是如何实现的——是打字机效果的文字展开时间，还是按钮延迟出现的等待时间？

**分析**: 代码中的"静默"实现是通过打字机效果完成的：按钮在 `textComplete` 之前是 `opacity-0`（不可见），文字以 40ms/字符 的速度展开。对于一句20个字符的台词，这大约是0.8秒；如果是30个字符则约1.2秒。

但 `silentAction`（沉默变体）场景下，文字是直接显示的（无打字机效果），然后按钮立即变为可见。这意味着沉默变体的"静默感"反而最短——它本应是最沉重的场景。

**建议**:
1. 沉默变体应有更长的"停顿"——文字出现后至少延迟2秒再显示按钮，让玩家在沉默中感受不安。
2. 在文档中明确各场景的最小展示时长：NEUTRAL 至少 1秒，GRATEFUL/RESENTFUL 至少 1.5秒，DESPERATE/沉默变体 至少 2.5秒。

### 12 ⭐ 打字机效果对离场台词的运用

**问题**: 无（亮点）。

**分析**: 代码使用 `TypewriterText` 组件逐字展开NPC台词，这个选择非常精准。40ms/字符的速度营造出"NPC正在艰难说出这句话"的感觉，尤其配合 RESENTFUL 和 DESPERATE 场景，每一个字符的出现都在加重情感的分量。

这符合 Schell 所说的"Poetry of Presentation"（呈现的诗意）——同样一句话，逐字出现比瞬间显示更有戏剧张力。

---

### 13 🟡 文档缺少"跳过"机制的设计立场

**问题**: 文档未讨论玩家是否能跳过送客环节，以及设计者对"跳过"的态度。

**分析**: 当前实现中，玩家必须等待打字机文字完成（或沉默变体的800ms延迟）后才能点击送客按钮。这是一种"软强制"——玩家不能跳过文字，但也不需要等太久。

然而，Rouse 的"玩家期望"理论指出，当玩家感觉被强制等待时，他们会产生抗拒心理，即使等待时间很短。特别是在重复进行游戏（存档/读档）或后期阶段（已见过大量台词），"不能跳过"会成为明显的体验摩擦点。

**建议**: 在文档中明确一个立场，并提供安全阀：
- **设计立场**: 送客环节不可跳过（强制面对后果是核心设计意图）
- **安全阀**: 允许点击文本区域加速打字机效果（将40ms/字符加速到5ms/字符），而非完全跳过。这保留了"必须看到"的设计意图，同时给予老玩家控制感。

## 亮点

- ⭐ **双层叙事结构**（发现1）: NPC退场台词 + 商人内心OS的序列设计优雅，自然构成微观兴趣曲线
- ⭐ **沉默变体**（设计文档系统五）: 20%概率的沉默离场打破了"总会说话"的预期，实现了"不说话比说话更有力"的效果
- ⭐ **无交易反馈面板**（发现7）: 让失败也有视觉重量，避免了"什么都没发生"的空洞感
- ⭐ **打字机效果**（发现12）: 逐字展现的叙事节奏赋予了每句台词戏剧张力
- ⭐ **内心OS文案质量**: "刚才那一瞬间，我看到了自己"这类短句做到了高密度的情感传达

## 总体评价

送客环节的核心设计意图——"强制留白，让玩家面对选择的后果"——是整个游戏情感体验的关键支柱。v1.1 采纳的沉默变体和内心OS在代码中的实现质量高于预期，打字机效果、头像情绪差分、内心独白文案都展现了对玩家情感节奏的细致考量。

然而，文档在两个关键维度上存在不足。**第一是"操作层空缺"**（发现2, 8）：送客阶段将玩家从议价的"高操作密度"瞬间降至"零操作"，且缺少从高潮到休息的过渡缓冲，这会导致体验的割裂感。**第二是"持续性设计缺失"**（发现3, 4, 5, 10）：文档几乎完全聚焦于"单次送客"的体验，而对"第30次送客"的疲劳风险、文案枯竭、情绪重复等长期问题缺乏预案。一个游戏流程可能包含60+次送客，如果每次都是相同节奏的"看台词 → 等800ms → 看内心OS → 点按钮"，这个本应是情感精华的环节将退化为玩家最想跳过的仪式。

建议优先处理发现2（增加最小限度的玩家能动性）和发现3（送客节奏的动态调节），这两项改进将从根本上决定这个环节在30天游戏流程中是持续有效还是逐渐失效。
