### Key Gaps

**Missing:**
1. **Gang threat event chain content (K.1):** The infrastructure for external triggers is fully built, but the specific `gang_threat` story chain has not been authored in any `.story` file. This is a content gap, not an architecture gap.
2. **Change notification protocol (L.3):** A process/documentation requirement for cross-system data contract change notifications. No enforcement mechanism exists in code.

**Partial:**
1. **Retrospective Log (F):** Currently implemented as raw simulation log entries (`recapLog`), not the richer NPC-narrated/diary-style format envisioned in the design document. The face-to-face emotional depth is limited.
2. **Emotional Escalation (H):** Stories follow the pattern organically (Emma: clothes -> laptop -> wedding ring), but there is no formalized "emotional weight tier" system in event chain types. The workshop system has `emotionalWeight.ts` separately.
3. **BehaviorTag mutual exclusivity validation:** Priority groups handle conflict resolution, but no creation-time validation prevents assigning mutually exclusive tags (e.g., NAIVE+SAVVY).
4. **Stage-specific behaviorTagOverrides:** Declared in data contract but not implemented as a field on `StoryEvent`. Per-event tags are set via customer template as a workaround.
5. **redemptionResolve dialogue mapping table:** The field exists but the explicit dialogue mapping (Strong -> "I'll definitely come back", etc.) is not formalized as a lookup table, relying on per-story DSL authoring.
6. **RETURN_VISIT interaction type:** Type defined but no story content uses it yet.
7. **Unified reputation pipeline:** External triggers route through SimRules, but contract-tier reputation effects in negotiation still bypass the event chain pipeline.

**Divergent:**
1. **Disposition type (5 vs 4):** Design specifies 5 psychological tendencies (desperate/firm/guarded/shrewd/sincere). Code `Disposition` type only has 4 (desperate/firm/bluffing/sincere), collapsing both SAVVY (shrewd) and SUSPICIOUS (guarded) into 'bluffing'. The `DesignTendency` type preserves all 5 values as a forward-looking bridge.
