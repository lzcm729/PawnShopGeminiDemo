# 周守义（Zhao）故事线改进计划

> 生成时间：2026-01-26
> 核心问题：**stress 变量完全隐形** — 玩家无法通过任何可视机制感知周老的压力递增，导致医院崩盘结局显得突兀

---

## 一、感知机制盘点

### 1.1 当前机制利用情况

| 机制 | 利用程度 | 问题 |
|------|----------|------|
| `description` 阶段递进 | 部分 | Stage 3 ("比上次更憔悴了") 有递进，但其他阶段变化不足 |
| `exitDialogues` 条件变体 | **未使用** | 所有 exitDialogues 都是静态文本，错失即时反馈机会 |
| `fateHints` 覆盖 | **未覆盖** | `stress` 和 `trust` 没有对应的 fateHint，玩家看不到核心状态变化 |
| 邮件系统 | **良好** | 丰富的邮件模板且大部分已调度 |

### 1.2 邮件调度审计

**已定义且已调度的邮件（正常）：**
- `mail_zhao_offer` - Stage 3 交易后 +1 天
- `mail_zhao_good` / `mail_zhao_good_extended` - Good Ending
- `mail_zhao_evil` - Evil Ending
- `mail_zhao_hostile` - Hostile Takeover
- `mail_zhao_sold_generic` - Core Lost
- `mail_zhao_plea` - 赎回失败时
- `mail_zhao_rumor` - Stage 1 交易后 +2 天
- `mail_zhao_hospital` - Stress >= 35 触发
- `mail_zhao_tragedy` - 最终赎回失败
- `mail_zhao_01_charity/shark` - Stage 1 即时反馈
- `mail_zhao_03_charity/shark` - Stage 3 即时反馈
- `mail_zhao_stress_warning` - Stress >= 15 触发
- `mail_zhao_health_warning` - Stress >= 25 触发
- `mail_zhao_hospital_update` - Shark 路径 +4 天
- `mail_zhao_redeem_success` - 勋章赎回成功

**总结：** 邮件系统较完善，覆盖了大部分关键节点。

## 二、玩家感知分析 [核心]

### 2.1 玩家视角时间线

```
Day 1: 周老出现 → "72岁老兵，腿脚不便，拄着拐杖"
       对话: "孙子下个月结婚...瞒着他的"
       玩家决策: 0%/5%/10%/20%
       ↓
Day 1: [邮件] mail_zhao_01_charity/shark (即时反馈)

Day 3: [邮件] mail_zhao_rumor (有人打听老物件)

Day 4: 收藏顾问出现 → "听说你收了一枚编号029的勋章？"
       玩家决策: 卖($5000) / 拒绝
       ↓
Day 4~5: [消失期间] 玩家不知道周老在做什么 ❌

Day 6+: 周老再出现 → "比上次更憔悴了，手里捏着医院缴费单"
       玩家能感知: description 变化
       对话有条件变体: greeting 根据 stress 变化
       玩家决策: 接受证书典当
       ↓
Day 6: [邮件] mail_zhao_03_charity/shark + mail_zhao_offer (+1天)

Day 8+: 周老来赎勋章
       ↓
Day 8: [如果赎回成功] mail_zhao_redeem_success
       [如果卖给顾问] → 直接 Evil Ending

Day 10+: 收藏顾问第二次 → $38,000 整套收购
       玩家决策: 卖 / 拒绝
       ↓

Day 12+: 周老来赎证书 → Good/Bad/Core Lost
```

### 2.2 感知盲区诊断

| 盲区 | 描述 | 影响 | 严重性 |
|------|------|------|--------|
| **Stress 隐形** | stress 是决定医院崩盘的核心变量，但玩家无法通过任何可视机制感知 | 玩家不知道自己的决策如何累积伤害 | **高** |
| **Trust 隐形** | trust 影响多处对话和结局质量，但玩家看不到变化 | 好结局体验缺乏递进感 | **中** |
| **exitDialogues 未利用** | 所有 exit 对话都是静态的，错失即时反馈机会 | 玩家离开谈判桌时没有即时的情感反馈 | **高** |
| **Day 4~6 消失期** | 周老在这期间做什么？玩家不知道 | 证书典当理由（医院押金）显得突兀 | **中** |
| **勋章重要性铺垫不足** | "这东西比我的命还重" 只在对话中一笔带过 | 玩家可能不理解为什么卖勋章是毁灭性的 | **中** |
| **战友遗物背景** | 勋章背刻他人姓名、牺牲名单等 Hidden Traits 需要高难度鉴定才能发现 | 叙事深度被埋藏 | **低** |

### 2.3 场景走查

#### 路径A：玩家全程善待周老（0%/5% + 拒绝收藏顾问）

```
Day 1: 给了好价格 → [邮件] "你是个公道人"
       玩家感知: ✓ 即时反馈良好

Day 6: 周老"比上次更憔悴" → 给了好价格
       玩家感知: ✓ description 变化可见
       但: 玩家不知道为什么更憔悴（stress 隐形）

Day 8: 来赎勋章 → 成功
       玩家感知: ✓ 有条件变体 "多亏你当时帮我一把"
       [邮件] "老伙计回家了"

Day 12: 来赎证书 → Good Ending
       [邮件] "爷爷在婚礼上戴着勋章证婚"
       玩家感知: ✓ 结局明确

问题:
- 中间过程（Day 2~Day 5）玩家不知道周老在做什么
- 好结局是"自然发生"还是"我努力的结果"？因果链不够清晰
```

#### 路径B：玩家剥削周老（20% + 接受高价收购）

```
Day 1: 高利率 → [邮件] "钱是少了点...腿的老毛病犯了"
       玩家感知: ✓ 即时反馈有

Day 4: [邮件] mail_zhao_hospital_update → "爷爷腿犯老毛病"
       玩家感知: ✓ 有消失期填补

Day 6: 周老出现 → greeting: "[老人的手在发抖，脸色发白]"
       玩家感知: ✓ 对话条件变体生效
       但: 这依赖 stress >= 20，而 stress 是隐形的

Day 8: Stress >= 15 → [邮件] 孙子担忧
       Stress >= 25 → [邮件] 医院健康警告
       Stress >= 35 → 住院崩盘
       玩家感知: ✗ 邮件来得突然，没有足够的前期铺垫

问题:
- 崩盘前的警告邮件依赖 stress 阈值，但 stress 递增是隐形的
- 玩家收到"爷爷状态不好"邮件时，可能困惑：我做了什么？
- 坏结局的心理递进对玩家来说不连贯
```

## 三、游戏设计理论评估

### 3.1 玩家期望检查

| 期望 | 当前状态 | 评估 |
|------|----------|------|
| **因果关系一致可预测** | 部分满足 | stress 影响结局但玩家看不到 |
| **理解行动边界** | 满足 | 玩家知道有卖/不卖、不同利率的选择 |
| **有公平的成功机会** | 满足 | 设计文档显示善意路径 GOOD 率约 51% |
| **不会无缘无故失败** | **不满足** | 医院崩盘可能让玩家困惑"我做错了什么" |

### 3.2 设计陷阱检测

| 陷阱 | 存在？ | 说明 |
|------|--------|------|
| 隐藏信息 | **是** | stress 变量完全隐藏，玩家失败却不知道原因 |
| 过度线性 | 否 | 有多条路径和分支 |
| 难度盲区 | 可能 | 设计者知道 stress 机制，玩家不知道 |

### 3.3 情感体验设计

周守义故事线的核心情感是 **尊严与荣誉** — 一个老兵为了给孙子体面的婚礼红包，不得不典当生死之交的遗物。

当前设计的问题：
- 勋章的情感重量在对话中提及，但玩家可能错过
- "张援朝"（背刻姓名）的故事需要高难度鉴定，大多数玩家不会发现
- 玩家卖掉勋章后的内疚感不够强烈，因为没有足够铺垫

## 四、改进方案概述

### 4.1 优先级排序

1. **[高] 为 stress 和 trust 添加 fateHints** — 让玩家能"看到"周老的状态变化
2. **[高] 升级 exitDialogues 为条件变体** — 利用即时反馈机制铺垫未来事件
3. **[中] 填补 Day 4~6 消失期** — 添加桥接邮件或调整现有邮件
4. **[中] 强化勋章情感铺垫** — 通过对话和邮件强调遗物意义
5. **[低] 检查 description 递进** — 确保每个阶段有合理变化

### 4.2 改进目标

| 目标 | 预期效果 |
|------|----------|
| 玩家能"看到" stress 变化 | 通过 fateHints 展示周老的身体状态 |
| 即时反馈强化 | exitDialogues 根据变量变化，让玩家当场感知决策影响 |
| 消失期填补 | 邮件让玩家知道周老在这期间经历了什么 |
| 因果链完整 | 坏结局时玩家能追溯"我的哪些决策导致了这个结果" |

## 五、验证清单

### 5.1 玩家感知验证

- [ ] 玩家第一次见到周老时，知道他的处境吗？→ ✓ 对话明确
- [ ] 每次交易后，玩家有收到反馈吗？→ 需升级 exitDialogues
- [ ] 周老消失的日子里，玩家知道他在做什么吗？→ 需添加桥接邮件
- [ ] 周老再次出现时，玩家能理解为什么状态变了吗？→ 需添加 stress fateHints
- [ ] 玩家能感知到自己的决策如何影响周老的命运吗？→ 需要 fateHints + exitDialogues
- [ ] 好结局让玩家感到"这是我努力的结果"吗？→ trust fateHints 帮助
- [ ] 坏结局让玩家感到"我本可以阻止这一切"吗？→ stress fateHints 帮助

### 5.2 场景走查验证（改进后预期）

**善待路径：**
```
Day 1: 好价格 → exitDialogue: "红包不用愁了！准时来赎！" (trust >= 60)
       → 玩家感知：周老很满意
Day 6: fateHint: "看到你时眼里有了光" (trust >= 70)
       → 玩家感知：我们的关系变好了
Day 12: Good Ending → 因果清晰
```

**剥削路径：**
```
Day 1: 高利率 → exitDialogue: "[深吸气] 钱是少了点..."
       → 玩家感知：周老不太开心，但勉强接受
Day 3: [邮件] "腿又犯了老毛病"
       → 玩家感知：他的健康在恶化
Day 6: fateHint: "手在发抖，指节发白" (stress >= 25)
       → 玩家感知：情况不妙，和我之前的决策有关系吗？
Day 7: [邮件] 孙子担忧
       → 玩家感知：确认了，周老状态越来越差
Day 8: 医院崩盘
       → 玩家感知：因果链完整，"我本可以不这么狠"
```

## 六、附录：与设计文档的对照

设计文档定义了：
- **Day 1~Day 16** 的完整时间线
- **Good/Bad/Evil** 三种结局
- **Stress >= 100** 崩盘机制

当前实现：
- 时间线基本对齐，但用 `stage` 而非严格的 `day` 控制
- 三种结局都有实现
- **Stress >= 35** 触发医院（比设计文档的 100 更激进）

差异分析：
- 实现中的 Stress 阈值较低（35 vs 100），可能是为了更快触发剧情
- 这意味着玩家更需要能感知 Stress 的变化，否则崩盘会显得突然
