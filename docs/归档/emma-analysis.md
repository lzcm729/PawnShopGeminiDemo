# 艾玛（Emma）故事线分析报告

> 生成时间：2026-01-26
> 分析方法：玩家感知优先 + 游戏设计理论框架

## 概述

艾玛是一名失业女白领，故事线围绕她从被裁员到重新找到工作（或彻底崩溃）的过程。玩家通过典当交易影响她的命运。

**核心张力：** 玩家的定价决策直接影响艾玛的心理状态（hope）和求职成功率（job_chance），最终决定她的结局。

---

## 一、玩家感知分析

### 1.1 玩家视角时间线

```
Day 1: 艾玛出现（Stage 0 → 1）
       物品：名牌职业套装
       玩家看到：年轻女性，穿着精致但焦虑
       对话透露：刚被裁员，暂时周转
       玩家决策：给价高/低

Day 1-2: 📧 即时反馈邮件（charity/shark）
         📧 状态更新邮件（hopeful/anxious，延迟2天）

[感知盲区 #1] Day 2-?: 等待 funds <= 200
         玩家不知道艾玛在做什么
         变量 hope、job_chance 在暗中变化

Day ?: 艾玛再次出现（Stage 1 → 2）
       物品：贵妇面霜礼盒
       玩家看到：妆容精致但疲惫
       对话变化：根据 hope 值有不同表现

[感知盲区 #2] Day ?-?: 等待 funds < 100
         没有延迟邮件填补空白

Day ?: 艾玛第三次出现（Stage 2 → 3）
       物品：笔记本电脑（生产工具）
       玩家看到：头发凌乱，黑眼圈重

[感知盲区 #3] Stage 3 = 等待期
         CHANCE 规则每天模拟面试
         玩家完全看不到这个过程

[分支 A] 面试成功 → Stage 5 → 好结局
[分支 B] hope < 10 → Stage 4（崩溃）→ 坏结局
[分支 C] 物品被卖 → 坏结局
```

### 1.2 感知盲区诊断

| 盲区 | 描述 | 影响 | 严重性 |
|------|------|------|--------|
| **男友角色缺失** | 男友从未在对话中出现，突然在Stage 4带着他的表来 | 坏结局缺乏铺垫，情感冲击削弱 | **高** |
| **求职过程不可见** | Stage 3的每日面试模拟玩家完全看不到 | 玩家不知道艾玛在努力还是在堕落 | **高** |
| **Stage 1-2过渡空白** | 从职业套装到面霜，中间只有一封延迟邮件 | 玩家无法理解恶化速度 | **中** |
| **Stage 2-3过渡空白** | 从面霜到电脑，没有延迟邮件 | "最后值钱的东西"来得太突然 | **中** |
| **hope/job_chance隐藏** | 核心变量完全不可见 | 玩家无法追溯决策影响 | **高** |
| **衣服的重要性** | 为什么卖了衣服=毁掉工作？缺乏事前解释 | 坏结局因果不清 | **高** |

### 1.3 场景走查

#### 路径A：玩家全程善待艾玛

```
Day 1: 慈善价收套装 → hope=70, job_chance=30
       📧 "谢谢你" + 📧 "近况汇报（乐观）"

Day 3: funds 逐日下降（-50/天）
       [空白期] 玩家不知道发生了什么

Day ~5: funds<=200 触发 → 艾玛带面霜来
       📧 "撑过这周"

Day ~8: funds<100 触发 → 艾玛带电脑来
       📧 "电脑的事"

Day 9+: Stage 3 每日模拟
       - job_chance=30 → 每天30%概率成功
       - 如果 hope>=80 → job_chance+2/天
       [玩家什么都不知道]

Day ~12: 如果成功 → 📧 "我拿到Offer了！"
         艾玛来赎回 → 好结局
```

**问题：** 好结局是"系统骰子决定的"，不是"玩家努力的结果"。玩家的慈善行为确实提高了 job_chance，但玩家感知不到这个因果。

#### 路径B：玩家全程剥削艾玛

```
Day 1: 高利贷价收套装 → hope=40, job_chance=10
       📧 "有总比没有好" + 📧 "有点焦虑"

Day ~3: 艾玛带面霜来
       📧 "这点钱..."

Day ~5: 艾玛带电脑来
       hope 被设为 20, job_chance 被减 10 → 接近 0

Day 6+: Stage 3 每日模拟
       - 如果 hope<30 → job_chance 每天-5 → 很快归0
       - 如果 hope<10 → 触发崩溃 → Stage 4
       📧 "一切都结束了"（男友离开）

Day ?: 艾玛带男士手表来
       [问题] 玩家："男友？什么男友？"
```

**问题：** 男友角色缺乏铺垫，坏结局的心理递进不够连贯。

## 二、游戏设计理论分析

### 2.1 玩家动机检查

| 动机 | 满足程度 | 问题 |
|------|----------|------|
| **情感体验** | 部分 | 物品递进设计好，但情感曲线断裂 |
| **挑战** | 低 | 玩家决策影响变量，但变量→结局的过程不透明 |
| **Fantasy** | 中 | "当铺老板决定他人命运"的幻想存在，但因果不清削弱了权力感 |

### 2.2 玩家期望对齐

| 期望 | 满足程度 | 问题 |
|------|----------|------|
| **因果一致** | ❌ | 玩家给高价 → hope 高 → job_chance 高，但玩家看不到这个链条 |
| **公平的机会** | ❌ | 面试是骰子决定的，玩家无法直接帮助艾玛成功 |
| **不被卡住** | ✓ | 故事会自动推进 |
| **理解边界** | ❌ | 玩家不知道"卖掉衣服"为什么是致命的 |

### 2.3 设计陷阱检测

| 陷阱 | 存在? | 表现 |
|------|-------|------|
| **隐藏信息** | ✓ | hope、job_chance、interview_failures 完全隐藏 |
| **过度线性** | 部分 | 物品顺序固定，但结局有分支 |
| **难度盲区** | ✓ | 设计者知道30%成功率不低，玩家觉得"随机" |

## 四、技术层面问题

### 4.1 缺少 deal_aid outcomes

Stage 1 (面霜) 和 Stage 2 (电脑) 的 outcomes 只有 `deal_charity`、`deal_standard`、`deal_shark`，缺少 `deal_aid`（5% 援助利率）。

### 4.2 赎回事件 targetItemId

`emma_05_redemption` 的 `targetItemId` 是 `emma_item_clothes`（衣服），这意味着衣服被卖掉会触发 `core_lost` 流程。设计意图是衣服=入职必需品，但叙事中未充分强调。

## 五、改进优先级

| 优先级 | 问题 | 原因 |
|--------|------|------|
| **P0** | 调度未使用的邮件 | 已有内容，只需添加调度 |
| **P0** | exitDialogues 添加条件变体铺垫男友 | 关键叙事盲区 |
| **P1** | Stage 3 面试进程反馈 | 核心感知盲区 |
| **P1** | 衣服重要性提前说明 | 因果清晰度 |
| **P2** | 添加 deal_aid outcomes | 技术完整性 |
| **P2** | fateHints 扩展 | 增强状态感知 |
| **P3** | 物品对话强化递进感 | 叙事打磨 |
