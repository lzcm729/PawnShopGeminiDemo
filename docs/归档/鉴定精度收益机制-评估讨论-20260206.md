## 1. 评估发现的问题

### 1.1 三档离散分级的可达性问题

原设计将 uncertainty 分为 LOW(<0.10) / MEDIUM(0.10~0.20) / HIGH(>0.20) 三档，MEDIUM 为基准（无收益）。

**问题**：鉴定 3 次（合理的 AP 投资量）只能到 uncertainty ≈ 0.184（MEDIUM），获得的是 ×1.00 基准——**三个方向全部零收益**。LOW 需要 ~7 次鉴定或发现 FAKE/JACKPOT 特征才能达到，这意味着"纯收窄"仍然没有价值。

### 1.2 方向 C（流当变现偏差）的因果感知问题

原设计：成交时记录 `uncertaintyAtDeal`，流当时计算变现偏差。

**问题**：
- 流当时玩家不知道真实价值，无法判断偏差是多少
- 黑市价格本身每日波动，uncertainty 导致的偏差会被市场波动掩盖
- 没有 A/B 对比场景——玩家无法建立"鉴定过 vs 没鉴定"的认知
- 因果链太长（成交→几天后→流当→结算），玩家已忘记当初的 uncertainty 状态

**结论**：一个感知不到的惩罚等于不存在。方向 C 需要重新设计落点。

### 1.3 方向 A（开价偏移）的叙事一致性

NPC 的 `currentAskPrice` 在生成时就固定了。如果鉴定实时改变已报出的价格，会破坏"NPC 一开口就报了价"的叙事一致性。

**建议**：A1 修正应在议价开始时一次性生效（进入 NEGOTIATION phase 时修正），不随后续鉴定再变。

### 1.4 方向 D（让步乘数）评价

**最干净的整合点。** 只需在 `pushPull.ts` 的 `concessionRatio` 上乘以精度乘数即可。改动量极小，效果立竿见影。

## 2. 设计决策

### 决策 1：改用连续函数（替代三档离散）

**理由**：消除 MEDIUM = 零收益的问题，让每次鉴定都有可感知的增量回报。

```
// uncertainty 范围 [0.05, 0.30]，映射到 [0, 1]
normalize(u) = clamp((u - 0.05) / 0.25, 0, 1)

// 连续映射
开价修正 = lerp(0.92, 1.08, normalize(uncertainty))
侮辱修正 = lerp(0.85, 1.10, normalize(uncertainty))
让步乘数 = lerp(1.30, 0.70, normalize(uncertainty))
```

鉴定 3 次（uncertainty ≈ 0.184）约获得 40% 进度的收益，而非原设计的零收益。

### 决策 2：保留方向 C 的非对称随机偏差

保留"赌博感"——HIGH uncertainty 时贬值概率大于增值概率。但落点从"流当一次性结算"改为"黑市波动"（见决策 3）。

### 决策 3：方向 C 改为"黑市波动幅度绑定 uncertainty"

**核心改造**：废弃原始 C 的 `uncertaintyAtDeal` + 流当偏差机制，改为让黑市出售价的波动幅度受物品 uncertainty 影响。

**当前代码**：`blackmarketService.ts` 中 `getRandomSaleMultiplier` 所有物品共享同一日波动范围 [0.60, 0.85]。

**改造后**：每件物品的波动幅度由 uncertainty 决定：

| uncertainty | 波动范围（围绕日基准） | 期望偏移 | 玩家感知 |
|-------------|----------------------|---------|---------|
| 0.05 (极低) | [-2%, +2%] | 0% | 价格稳定 |
| 0.15 (中等) | [-12%, +6%] | -3% | 有波动，略偏低 |
| 0.30 (极高) | [-30%, +10%] | -10% | 剧烈波动，经常跳水 |

**非对称性保留**：下行幅度始终大于上行幅度，uncertainty 越高越明显。

**收购轨也适用**：黑市收购价加入精度修正：
- LOW → ×1.00（黑市信任你的鉴定，全价收购）
- HIGH → 波动且偏低（黑市也不确定值多少，倾向压价）

**流当结算改造**：流当自动结算 = 按当天该物品的黑市出售价卖出（已包含 uncertainty 波动），不再需要单独的流当偏差机制。

### 为什么新 C' 比原始 C 更好

| 维度 | 原始 C（流当一次性偏差） | 新 C'（黑市波动绑定 uncertainty） |
|------|------------------------|----------------------------------|
| 感知时机 | 流当结算时（延迟，已忘因果） | 每天打开黑市都能看到（持续） |
| 对比基准 | 无（不知道"本来能卖多少"） | 同一界面，鉴定 vs 未鉴定物品并列 |
| 归因清晰度 | 模糊（市场差 or 没鉴定？） | 清晰（同天同类物品，波动幅度不同） |
| 决策空间 | 无（已流当，无法补救） | 有（等好价 vs 割肉，本身是新决策） |
| 新增 UI | 需要专门的结算演出 | 零——复用现有黑市价格显示 |
| 系统耦合 | 新增独立机制 | 增厚现有黑市系统 |

## 3. 废弃的方案

### 方案 3："变现信心"UI 指标

在成交入库时显示信心条（如"变现信心 95%"）。

**废弃理由**：玩家通过估值范围 + 当金已经能判断盈亏风险，信心指标是冗余信息。违反 Sylvester 优雅性启发（负担增加但力量没增加）。

### 原始方向 C：`uncertaintyAtDeal` + 流当变现偏差

成交时记录 uncertainty 等级，流当时计算随机偏差。

**废弃理由**：因果感知问题无法解决（见 1.2）。改为黑市波动方案后，不再需要 `uncertaintyAtDeal` 字段。

## 4. 最终三方向设计

```
时间线 ───────────────────────────────────────────────────▶

鉴定阶段       议价开始         推拉过程        库存管理/卖出
  |               |                |                |
  |         [A 即时感知]     [D 渐进感知]     [C' 持续感知]
  |         开价修正          让步幅度加速     黑市波动幅度
  |         侮辱线修正                        收购价精度修正
  v               v                v                v
花费 AP      "开价低了！"      "让步快了"     "价格真稳/真跳"

全部使用连续函数，uncertainty 越低收益越大，每次鉴定都有增量回报。
```

## 5. 实现分工

| 层 | 工作内容 |

| **Framework** | 连续函数工具函数（uncertainty → 修正系数映射）；议价注入 A1（开价修正，议价开始时一次性生效）、A2（侮辱线修正）、D（让步幅度乘数）；黑市波动改造 C'（`getRandomSaleMultiplier` 引入物品级波动）；收购轨精度修正；流当结算改走黑市出售价 |
