# 全量差距分析流程

执行完整的设计-实现差距分析时参考此模板。

## 分析流程

### 1. 枚举设计文档

读取 `Designer/系统设计文档/` 目录，从每个文档提取：
- 系统名称
- 核心功能列表

### 2. 枚举代码实现

扫描 `systems/` 目录结构，识别已有代码的系统。

### 3. 分类对比

| 状态 | 条件 |
|------|------|
| **已实现** | 设计存在 + 代码存在 + 功能匹配 |
| **部分实现** | 设计存在 + 代码存在 + 功能不完整 |
| **未实现** | 设计存在 + 无代码 |
| **仅代码** | 代码存在 + 无设计文档 |

### 4. 深度功能检查（针对部分实现的系统）

1. 读取设计文档的功能列表
2. 搜索代码中的对应实现
3. 列出缺失功能

## 输出格式

```markdown
## 设计-实现差距分析

### 系统实现状态

| 系统 | 设计文档 | 代码目录 | 状态 |
|------|---------|---------|------|
| 鉴定系统 | yes | hooks/useAppraisal.ts | done |
| 黑市系统 | yes | - | pending |

### 部分实现系统详情

#### [系统名]
**设计文档:** `Designer/系统设计文档/xxx.md`
**代码位置:** `systems/xxx/`

| 功能 | 设计 | 实现 |
|------|------|------|
| 功能A | yes | yes |
| 功能B | yes | missing |

### 未实现系统

1. **黑市系统** - 设计完成，待实现

### 建议优先级

1. [系统名] - [原因]
```
