# 感知机制详解与检查清单

## 玩家感知机制层次

| 层次 | 机制 | 时机 | 条件变体支持 | 说明 |
|------|------|------|--------------|------|
| 视觉层 | `description` | 客户出现时 | 静态字符串 | 描述 NPC 外观状态 |
| 视觉层 | `observation` (fateHints) | 客户出现时 | 基于变量动态生成 | 补充细节观察 |
| 对话层 | `greeting`, `pawnReason` 等 | 对话过程中 | `DialogueVariant[]` | 根据变量选择不同台词 |
| 对话层 | `exitDialogues` | 交易结束时 | `DialogueVariant[]` | **常被忽略！可用于即时反馈和铺垫** |
| 延迟层 | 邮件系统 | 交易后 N 天 | - | 填补 NPC 消失期间的信息空白 |

## 各机制最佳用途

| 机制 | 最佳用途 | 示例 |
|------|----------|------|
| `description` | 展示 NPC 外观状态变化 | "头发凌乱，黑眼圈很重" |
| `observation` | 展示细节、暗示内心状态 | "（她的手在发抖）" |
| `exitDialogues` | **即时反馈 + 铺垫未来事件** | "回去又要听他抱怨了..." |
| 邮件（即时） | 交易后情感反馈 | "谢谢你帮我" |
| 邮件（延迟） | 填补消失期间、铺垫下次出现 | "面试被拒了，但我不会放弃" |

## 盘点检查清单

### 1. description 递进检查
- [ ] 每个阶段的 description 是否有变化？
- [ ] 变化是否反映了 NPC 状态的递进？（如：精致→疲惫→凌乱→枯槁）

### 2. 对话条件变体检查
- [ ] `greeting`、`pawnReason` 是否使用了条件变体？
- [ ] `exitDialogues` 是否使用了条件变体？（**重点！**）
- [ ] 条件变体是否覆盖了关键变量的不同区间？

### 3. fateHints 覆盖检查
- [ ] 该故事线的核心变量是否有对应的 fateHint？
- [ ] 变量的中间状态（如 hope 30-60）是否有覆盖？

### 4. 邮件系统检查
- [ ] 每个阶段过渡是否有即时邮件？
- [ ] 是否有延迟邮件填补消失期间？
- [ ] **是否有已定义但未调度的邮件？**

## 常见问题：已定义但未使用的资源

**务必检查！** 使用 Grep 搜索邮件模板 ID，确认是否出现在某个 `SCHEDULE_MAIL` 中：

```
# 示例：检查某个邮件是否被调度
Grep: "mail_emma_stage2_struggling"
# 如果只出现在定义处，没有出现在 outcomes 或 simulationRules 中，说明未被使用
```

## 玩家感知分析检查清单

### 感知盲区检查
- [ ] 玩家第一次见到NPC时，知道她/他的处境吗？
- [ ] 每次交易后，玩家有收到反馈吗？（exitDialogues + 邮件）
- [ ] NPC消失的日子里，玩家知道她/他在做什么吗？
- [ ] NPC再次出现时，玩家能理解为什么状态变了吗？
- [ ] 玩家能感知到自己的决策如何影响NPC的命运吗？

### 结局体验检查
- [ ] 好结局让玩家感到"这是我努力的结果"吗？
- [ ] 坏结局让玩家感到"我本可以阻止这一切"吗？
- [ ] 隐藏变量（如hope、job_chance）有通过可见方式体现吗？

### 叙事铺垫检查
- [ ] 重要角色（如男友）是否有提前铺垫？
- [ ] 关键物品的重要性是否事前说明？（而非事后才知道）

## 结合游戏设计理论分析

在分析故事链时，结合 `game-design-theory` 提供的框架：

### 1. 玩家动机检查
- 这条故事线满足了哪些玩家动机？（挑战、社交、情感体验、幻想...）
- 道德困境是否提供了有意义的情感体验？

### 2. 玩家期望对齐
- 因果关系是否一致且可预测？
- 玩家是否有公平的机会成功？
- 玩家是否清楚自己的行动边界？

### 3. 涌现性与非线性
- 玩家的选择是否能产生设计师未预期的故事走向？
- 是否有多条有意义的路径通向不同结局？

### 4. 设计陷阱检测
- 是否存在"隐藏信息"问题？（玩家失败却不知道原因）
- 是否存在"过度线性"问题？（玩家感觉被牵着走）
- 是否存在"难度盲区"？（设计者觉得简单但玩家觉得难）
